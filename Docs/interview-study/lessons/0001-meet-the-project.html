EmberlightWandere 架构课 · 第 1 课

打开项目，你几乎什么都看不到

你说代码是 AI 写完的、你一直没管。这不是你一个人的问题——这个项目在设计上就没打算让人看懂： 打开 Unity，你找不到任何可以「点进去看看」的东西。 这一课先解决这件事：让你在编辑器里看见它真实的样子。

本课唯一目标：在 Unity 里指出 Emberlight Game 这个物体，并说出它上面挂着哪个脚本、这个脚本负责什么。
本课不要求你读懂那个脚本里的一行代码。那是下一课的事。

1先说结论：场景里只有 3 个物体

打开主场景 Assets/Scenes/Emberlight.unity，Hierarchy 窗口里是这样：

Emberlight GameTransform +
EmberGame（唯一的脚本）		整个游戏的唯一入口

这就是你「看不懂」的第一个原因

打开场景，你看到的是一个几乎空的编辑器。没有 Player、没有 Enemy、没有 HUD、没有按钮——没有任何东西可以点进去、顺着找到代码。

教程里的项目，Hierarchy 里摆着一堆物体，你点一个就能看到管它的脚本。这个项目把这条路堵死了。

2为什么「没挂上去」等于「不会跑」

Unity 有一条最基础、但这个项目把它用到极致的规则：

Unity 的基本规则

你写的 .cs 文件本身是死的。它必须被挂到某个 GameObject 上、成为一个组件，Unity 才会去调用它的 Start()、Update() 这些方法。

没挂上去的类，就是一份普通代码，等着别人 new 它。

现在把这条规则和你项目里的数字对一下：

数量后果
Assets 下的 .cs 文件4640 个运行时 + 6 个编辑器脚本
能挂到物体上的类（继承 MonoBehaviour）10只有它们具备「被引擎调用」的资格
场景里实际挂上去的脚本1EmberGame——就它一个

也就是说：按下 Play 之前，除 EmberGame 以外的整个世界都还不存在。

3那游戏里的东西是哪来的？

答案：全部是运行时用代码造出来的。你按下 Play 的那一刻，EmberGame 才开始一行一行地把这个世界 new 出来。

4动手 · 亲眼看见它长出来（约 10 分钟）

这一课的核心体验只有一个：看见一棵树从无到有长出来，再看着它消失。请真的打开 Unity 走一遍。

  1. 打开主场景。在 Project 窗口里找到 Assets/Scenes/Emberlight.unity，双击。
  2. 数一数 Hierarchy。确认只有 3 项：Main Camera、Emberlight Game、Main Light。

    如果层级窗口里东西很多，说明你开的不是这个场景（另一个 SampleScene.unity 没有启用，忽略它）。

  3. 点中 Emberlight Game，看 Inspector。确认里面的组件只有 Transform 和 EmberGame。
  4. 做那个以后要用几百次的动作：在 Inspector 里双击 EmberGame 这个组件名（或者右键 → Edit Script）。 Unity 会打开 Assets/Scripts/Core/EmberGame.cs。

    这就是「从游戏里的东西找到管它的代码」。这个项目只有一次练习机会（就这一个脚本），但思路是通用的。

  5. 顺手确认另外两个物体没有脚本。分别点中 Main Camera 和 Main Light，看 Inspector——都只有内建组件，没有 MonoBehaviour。
  6. 按 Play。等加载页过去、进到主菜单之后，回来再看 Hierarchy。

    Emberlight Game 左边出现了展开箭头，下面长出了一整棵 UI 树。

  7. 把树展开看一遍。Emberlight Game → Emberlight UI → Safe area，你会看到 Overlay、Joystick，以及挂在 Safe area 上的几个面板组件。 这些在 Play 之前一个都不存在。
  8. 停止 Play。Hierarchy 缩回 3 项。

    因为运行时造出来的东西不会被保存——它们是临时的。

你从这一步拿到的结论

编辑器里空旷 ≠ 项目简单。这个项目的复杂度全部藏在代码里，不在场景里。

也正因为如此，「没看过代码」在这里等于「完全不知道游戏是怎么做出来的」——这不是懒，是这个项目的结构决定的。

6这一课之后，你应该知道的三件事

  • 场景 Emberlight.unity 里只有 3 个物体，只有 Emberlight Game 上挂了脚本。
  • 那个脚本叫 EmberGame，是整个游戏唯一的入口。
  • 除它以外的一切（UI、主角、敌人、子弹）都是运行时由代码创建的。

现在再回头看你之前听到的那些名字——EmberCombat、RunProgress、EmberWeapon——它们都是被 EmberGame 叫起来干活的对象，不是引擎驱动的。

还有一件事值得注意

全项目 10 个 MonoBehaviour 里，有 4 个（EmberEnemySilhouette、EmberGodsSelectPanel、EmberUpgradePanel、EmberSettingsPanel）连一个生命周期函数都没有。它们继承 MonoBehaviour 只是为了「能被 AddComponent 挂上去」，并不是想让引擎每帧叫它们。

所以「继承 MonoBehaviour」≠「会被引擎驱动」。判断一个类会不会自己动，要看它有没有 Start / Update 这类方法。
