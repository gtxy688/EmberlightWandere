# 07. 单局流程与配置模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

创建和连接各系统，保存阶段与本局引用，协调开局、选卡、暂停、结算和返回；配置提供本局及武器共用规则。

这里安排谁先执行、结果交给谁，不把生命、候选或武器规则全部写在入口里。配置随各模块的使用点穿插阅读。

## 从哪里接入

先认识 EmberRunPhase，再看 EmberGame 的字段、Awake、Start 与 Update。首次只建立装配和调用顺序，之后回到同一文件逐段覆盖开局、暂停、选卡、结算和宿主回调。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 阶段和本局容器

[EmberRunPhase.cs](../../../Assets/Scripts/Core/EmberRunPhase.cs)、[IEmberRunPhaseSource.cs](../../../Assets/Scripts/Core/IEmberRunPhaseSource.cs)、[EmberRunState.cs](../../../Assets/Scripts/Core/EmberRunState.cs)。

区分当前阶段、只读契约、构筑数据与场景引用；未读类型先只认识接口作用。

### 2. 组合入口

[EmberGame.cs](../../../Assets/Scripts/Core/EmberGame.cs)。

按字段和生命周期、StartRun、选卡回流、Pause、EndRun、ReturnToCamp、宿主实现逐段连续读，最终补齐整个脚本。

### 3. 本局配置

[LevelConfig.cs](../../../Assets/Scripts/Core/LevelConfig.cs)。

从 Create 和 ApplyWorld 接入，随波次、敌人和掉落使用点补齐全部配置与查询方法。

### 4. 武器共用参数

[EmberWeaponTuning.cs](../../../Assets/Scripts/Core/EmberWeaponTuning.cs)。

在升级、攻击与预览的使用点穿插查看，随后核对全部武器参数。

### 5. 游戏速度

[GameSpeed.cs](../../../Assets/Scripts/Core/GameSpeed.cs)。

看倍速如何保存与应用，再结合 Playing、Paused 和返回时的处理。

## 结合哪些场景、配置与资源

[Emberlight.unity](../../../Assets/Scenes/Emberlight.unity)、[EditorBuildSettings.asset](../../../ProjectSettings/EditorBuildSettings.asset)、[ProjectSettings.asset](../../../ProjectSettings/ProjectSettings.asset)、[TimeManager.asset](../../../ProjectSettings/TimeManager.asset)。

主场景需核对入口脚本的 UI、加载页和 ArtSet 引用；工程配置还涉及场景启用、平台、时间与分辨率。

## 怎样接到其他模块

认识入口后进入玩家操作，再沿实际调用进入构筑、武器和战斗；所有模块读过后，回到这里串一次启动、暂停、结算与重开。当前导航不是已读证明，状态只记在总地图。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
