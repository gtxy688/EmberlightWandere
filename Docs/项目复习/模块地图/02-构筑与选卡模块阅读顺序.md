# 02. 构筑与选卡模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

保存武器拥有状态和升级结果，生成当前可选的卡，管理清波后的选卡次数与补偿。

候选卡怎样显示由界面处理，卡片被选择后怎样改变构筑在这里处理；武器再读取构筑结果执行攻击。

## 从哪里接入

从 EmberGame.StartRun 中创建 RunProgress 接入，再看 OnWaveCleared、SelectUpgrade 和 TryRefreshOffer 怎样把操作交给 RunFlowController。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 武器和词条身份

[EmberWeaponCatalog.cs](../../../Assets/Scripts/Core/EmberWeaponCatalog.cs)。

先认识武器、通用词条、专属和质变的 Id 与映射，知道后面的查询依据什么。

### 2. 品质与候选数据

[EmberRarity.cs](../../../Assets/Scripts/Core/EmberRarity.cs)。

覆盖文件中的枚举、工具和 EmberOffer，区分品质、候选类型与候选内容。

### 3. 本局构筑

[RunProgress.cs](../../../Assets/Scripts/Core/RunProgress.cs)。

从 ConfigureRun 读拥有状态和属性，再覆盖候选入口、Choose、刷新、护盾与计分。共享数值遇到时穿插查看 EmberWeaponTuning。

### 4. 候选生成

[EmberChoicePool.cs](../../../Assets/Scripts/Core/EmberChoicePool.cs)。

看它读取哪些状态，怎样决定候选数量、条件、去重和随机抽取。

### 5. 选卡流程

[RunFlowController.cs](../../../Assets/Scripts/Core/RunFlowController.cs)。

先读 Host 约定，再连续覆盖清波、发卡、选择、刷新与补偿结束。

## 结合哪些场景、配置与资源

数值来源随使用点回看 LevelConfig、EmberWeaponTuning；卡牌视图与 UIRoot 在界面模块阅读。相关规则测试统一列在开发工具与测试模块。

## 怎样接到其他模块

读完后回到 EmberGame 的选卡回调，分清规则结果、阶段切换与界面呈现，再把 RunProgress 的只读查询接到武器模块。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
