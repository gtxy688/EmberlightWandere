# 01. 玩家操作与生命模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

接收触屏、鼠标或键盘操作，把摇杆方向交给移动代码；生命代码处理受伤、护盾、无敌帧和治疗。

输入负责产生操作意图，移动负责改变位置，生命结算返回结果；是否暂停、是否结束本局，由单局流程衔接。

## 从哪里接入

从 EmberGame.Update 中的 input.Tick、EmberKeeperMotion.Step 接入，再从 HurtPlayer 和 PickHealingDrop 找到生命结算。这里只追踪玩家自身的操作和数值，敌人怎样造成伤害在战斗模块阅读。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 操作输入

[EmberInput.cs](../../../Assets/Scripts/Core/EmberInput.cs)。

先看 Presenter 约定、Tick、Reset 和 KeyboardAxis，弄清输入怎样变成方向，暂停请求交给谁。

### 2. 位移与相机

[EmberKeeperMotion.cs](../../../Assets/Scripts/Core/EmberKeeperMotion.cs)。

沿 Step、Follow 看位置、边界与相机跟随，知道它读取哪些本局引用。

### 3. 结算结果

[EmberVitalOutcome.cs](../../../Assets/Scripts/Core/EmberVitalOutcome.cs)。

认识拒绝、已结算但未改变、数值改变这些结果，方便理解调用方的后续动作。

### 4. 生命规则

[EmberKeeperVitals.cs](../../../Assets/Scripts/Core/EmberKeeperVitals.cs)。

读构造依赖，再覆盖 Reset、Tick、受伤、治疗与 CommitHealthChange；把护盾、生命和失败判断分开。

## 结合哪些场景、配置与资源

[InputManager.asset](../../../ProjectSettings/InputManager.asset)、[TimeManager.asset](../../../ProjectSettings/TimeManager.asset)、[Emberlight.unity](../../../Assets/Scenes/Emberlight.unity)。

对照输入设置与主场景相机，再回看 GameSpeed 对游戏时间的应用。不要从设置文件的存在推断每个输入轴都被使用。

## 怎样接到其他模块

位移读取 Buff 的移速结果，生命规则会用到本局构筑和难度；首次遇到这些类型只认识接口作用，随后进入构筑、Buff 和配置模块。对应生命测试在开发工具与测试导航中。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
