# 05. Buff模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

保存临时效果定义与生效实例，管理持续时间，汇总移动和伤害等属性修正。

掉落与敌人技能提出施加请求，单局入口接到管理器；移动、伤害读取结果，界面显示效果与剩余时间。

## 从哪里接入

从 EmberGame.TryAddBuff 和 Update 中的 Run.Buffs.Tick 接入，先分清效果由谁添加、由谁推进。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 共享定义

[BuffConfig.cs](../../../Assets/Scripts/Core/Buffs/BuffConfig.cs)。

认识属性分类、效果身份和不可变规则。

### 2. 生效实例

[Buff.cs](../../../Assets/Scripts/Core/Buffs/Buff.cs)。

区分一次生效的剩余时间与共享配置，知道谁有权刷新和推进实例。

### 3. 管理与汇总

[BuffManager.cs](../../../Assets/Scripts/Core/Buffs/BuffManager.cs)。

连续读添加、同 Id 刷新、Tick、清除和属性汇总，不把临时修正当作直接改写基础属性。

### 4. 项目当前效果

[EmberBuffCatalog.cs](../../../Assets/Scripts/Core/Buffs/EmberBuffCatalog.cs)。

把通用规则对应到实际增益和减益定义。

## 结合哪些场景、配置与资源

本模块先读纯逻辑；Buff 图标、计时环、说明和浮字在界面表现模块登记完整阅读，效果施加来源回查掉落与敌人技能。

## 怎样接到其他模块

读完后回看移动、伤害和 HUD 的读取点，区分玩法计时与展示计时。到期、刷新、暂停、重开之间的完整关系可留到关键流程精读。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
