# 03. 武器与伤害模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

实现六把武器的攻击行为，并把命中交给伤害结算；共享燃地保存持续伤害区域。

武器从构筑读取拥有状态和升级，使用战斗提供的目标、池与伤害服务；敌人的创建、回收和整波推进属于敌人与波次模块。

## 从哪里接入

从 EmberCombat 的武器列表、BindWeaponContext 和 TickWeapons 接入，先知道武器拿到了哪些服务，再进入单把武器。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 共用服务与注册

[EmberWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberWeapon.cs)、[EmberWeaponFactory.cs](../../../Assets/Scripts/Combat/Weapons/EmberWeaponFactory.cs)。

看上下文、武器基类、音效标识与注册顺序，不要求先记住所有委托的实现。

### 2. 一次伤害的结果

[EmberCombatDamage.cs](../../../Assets/Scripts/Combat/EmberCombatDamage.cs)。

认识 Context、Apply 与返回结果的使用；随后读完整文件，留意死亡、分裂与重生相关处理。

### 3. 第一把武器

[EmberBasicShotWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberBasicShotWeapon.cs)。

从火球串起选敌、冷却、发射、运动、命中与回收，作为后续武器的参照。

### 4. 环绕与路径攻击

[EmberOrbitWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberOrbitWeapon.cs)、[EmberTrailWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberTrailWeapon.cs)。

分别看环绕接触伤害与路径燃地，不把相似的画面表现当成同一套结算。

### 5. 共享燃地

[EmberBurnGround.cs](../../../Assets/Scripts/Combat/EmberBurnGround.cs)。

看区域创建、持续时间、伤害推进和视图回收，再回查调用方。

### 6. 其余攻击形态

[EmberPierceWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberPierceWeapon.cs)、[EmberBoomerangWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberBoomerangWeapon.cs)、[EmberMeteorWeapon.cs](../../../Assets/Scripts/Combat/Weapons/EmberMeteorWeapon.cs)。

按穿透与分裂、往返命中、预警与范围结算逐个读；每个文件覆盖初始化、推进和清理。

## 结合哪些场景、配置与资源

参数使用点回查 EmberWeaponTuning，构筑查询回查 RunProgress；弹体、粒子和对象池先认识接口，具体来源在表现与战斗导航补齐。

## 怎样接到其他模块

伤害结果交回 EmberCombat 处理死亡、计分、掉落和波次计数。随后进入敌人与波次，核对这一端怎样收尾；共享燃地和性能用例见测试导航。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
