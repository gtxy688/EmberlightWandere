# 04. 敌人与波次模块阅读顺序

本文件负责阅读入口、顺序和模块交接；实际已读范围、理解状态与疑问只记录在[总地图](../00-源码阅读地图.md)。

## 这一部分解决什么问题

组织每帧战斗，决定波次与遭遇，创建和回收敌人，推进兵种行为、Boss 招式、暗弹与掉落。

波次决定何时提出生成请求，名册实际持有敌人，行为代码改变敌人动作；战斗入口把这些步骤和武器、死亡处理接起来。

## 从哪里接入

从 EmberGame.Update 调用 combat.Tick 接入，先看 EmberCombat.Begin、Tick 和 TearDown，建立这一局战斗的开始、推进和清理顺序。

这份顺序是导航。正式开始新文件时，仍需结合当前理解先介绍职责、与已读内容的关系和本次阅读范围，不把整张清单作为一次阅读任务。

## 建议阅读顺序

### 1. 宿主与战斗入口

[IEmberCombatHost.cs](../../../Assets/Scripts/Combat/IEmberCombatHost.cs)、[EmberCombat.cs](../../../Assets/Scripts/Combat/EmberCombat.cs)。

先认识战斗能读取和请求的能力，再分段覆盖装配、每帧推进、上下文接线、死亡处理和拆除。

### 2. 敌人数据与空间

[EmberEnemy.cs](../../../Assets/Scripts/Combat/EmberEnemy.cs)、[EmberWorld.cs](../../../Assets/Scripts/Combat/EmberWorld.cs)。

读单个敌人的状态、地图限制和可见范围；EmberWorld 文件还包括 EmberEnemyBar，不漏掉同文件类型。

### 3. 复用与生成

[EmberPool.cs](../../../Assets/Scripts/Combat/EmberPool.cs)、[EmberSpawnPlacement.cs](../../../Assets/Scripts/Combat/EmberSpawnPlacement.cs)、[EmberEnemyRoster.cs](../../../Assets/Scripts/Combat/EmberEnemyRoster.cs)。

把取用视图、寻找屏外合法点、配置敌人和回收连起来。

### 4. 波次推进

[EmberWaveDirector.cs](../../../Assets/Scripts/Combat/EmberWaveDirector.cs)。

看 Host 约定、Begin、波次切换和 Tick，再覆盖遭遇、Boss 伴随兵与清波条件。

### 5. 行为与招式

[EmberEnemyBehavior.cs](../../../Assets/Scripts/Combat/Enemies/EmberEnemyBehavior.cs)、[EmberBoss.cs](../../../Assets/Scripts/Combat/EmberBoss.cs)、[EmberEnemyProjectiles.cs](../../../Assets/Scripts/Combat/Enemies/EmberEnemyProjectiles.cs)。

先读行为接口和上下文，再按兵种看动作；Boss 与暗弹单独覆盖，不假定它们由独立 Update 驱动。

### 6. 掉落与表现

[EmberDrops.cs](../../../Assets/Scripts/Combat/EmberDrops.cs)、[EmberEnemyVisual.cs](../../../Assets/Scripts/Combat/Enemies/EmberEnemyVisual.cs)、[EmberEnemySilhouette.cs](../../../Assets/Scripts/Combat/Enemies/EmberEnemySilhouette.cs)。

读治疗／Buff 掉落的生成、吸附和拾取，再看兵种外观、皮肤与攻击预警。

## 结合哪些场景、配置与资源

[CleanToonSample/Prefabs](../../../Assets/Art/CleanToonSample/Prefabs)、[CleanToonSample/Enemies](../../../Assets/Art/CleanToonSample/Enemies)。

结合 Shade 模板、皮肤映射、盾图、材质和导入切片。难度、配额、间隔与敌人属性随 LevelConfig 使用点查看。

## 怎样接到其他模块

清波请求交回选卡流程，掉落与敌人技能通过宿主施加生命变化或 Buff。复杂的死亡、重生、分裂与清波关系留到精读；相关测试见第 08 份导航。

共享文件的完整通读归属见总地图；这里只从相关接口回查，不重复登记进度。模块内的文件组用于组织阅读，一个文件分段阅读时仍需明确类型、方法或代码段。

## 模块收尾时核对

核对本模块仍然未读、部分已读、待确认和暂跳过的文件，补上新发现的自有源码，以及影响行为的配置和绑定。入口读完不代表整个模块完成。

读完后把职责、主要数据和协作关系整理为模块笔记，具体卡点保留到总地图或对应问题文档。静态阅读不能确认的行为再按需要验证。
