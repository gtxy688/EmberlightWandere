# 实现说明

本文是《烬灯行者》的工程实现与开发维护手册。如果你需要改代码、排查 Bug、加新武器、换美术资源，或者准备打包交付，按本文的指引查阅和操作。

设计上的思考与权衡见 [技术分析](技术分析.md)；完整模块职责与任务路由见 [架构总览](architecture/00-overview.md)；产品规则与数值权威统一见 [需求文档](requirements.md)。

---

## 1. 工程入口与快速上手

1. **引擎版本**：**Unity 2022.3.62f3** 。
2. **唯一主场景** `Assets/Scenes/Emberlight.unity` 。
3. **开局流转**：
   - 首次启动显示加载页（`IntroRoot`），字体与资源校验就绪后按任意键进入主菜单（`UIRoot`）。
   - 点击开始游戏，**依次完成四步选择**：选择局长（25 波 / 50 波）→ 选择难度（休闲 / 标准 / 困难）→ 选择武器槽位上限 N（1~5）→ 点选 1 把起始武器。选完后点击确认正式开战。
4. **局内操作**：
   - 电脑端用 WASD 或用鼠标直接拖动屏幕下半部的虚拟摇杆移动；移动端直接拖动屏幕下半部的虚拟摇杆移动。
   - 所有武器**全自动索敌与开火**，无需手动瞄准。
   - 按键盘 Esc 键或点击右上角齿轮按钮唤出暂停菜单（可调音量、查看当前构筑、放弃本局）。

## 2. 单局生命周期与一帧之内干了啥

### 2.1 整局状态流转（生命周期）

整个单局的状态完全由组合根 `EmberGame` 的 `phase`（`EmberRunPhase` 枚举）统一管理，状态流转非常清晰：

```text
[打开工程运行]
       │
       ▼
    Booting（校验预烘字体、初始化加载页 IntroRoot）
       │
       ▼
    CampMenu（营地主菜单，玩家点击“开始游戏”）
       │
       ▼
    SelectingLength → SelectingDifficulty → SelectingSlotCount → SelectingWeapon
       │（四步严格选择，不可跳过）
       ▼
    Playing（正式开战，创建玩家、初始化战斗与武器，持续推进波次）
       │                 │
       ├─ 暂停/选卡 ─────┤ （阶段切为 Paused 或 Upgrading：
       │                 │   战斗逻辑与计时立即完全冻结，界面动画与非缩放时钟正常跑）
       ▼                 ▼
    Victory（通关） 或 Defeat（阵亡）
       │
       ▼
   展示结算大板（显示耗时、波次、击杀数、最终积分）
       │
       ▼
   点击返回营地（触发 ReturnToCamp：彻底清理本局怪物、子弹、掉落与构筑，保留 UI 回到 CampMenu）
```

### 2.2 一帧之内干了啥（Update 推进时序）

整个游戏只有 `EmberGame` 一个入口脚本挂在场景物体上。所有的子系统都不自己偷偷跑 `Update`，而是由 `EmberGame.Update` 在 `Playing` 阶段像流水线一样按死顺序统一调度：

```text
EmberGame.Update（仅在 Playing 阶段往下推进）
  │
  ├─ 1. 基础时钟与输入处理
  │    - 累计单局生存时间、更新无敌帧倒计时
  │    - EmberInput 采集键盘与虚拟摇杆输入，合成归一化移动向量
  │
  ├─ 2. 状态倒计时与玩家位移
  │    - 推进玩家 Buff 倒计时（到期自动注销并重新汇总属性加成）
  │    - EmberKeeperMotion 驱动玩家移动并做地图边界碰撞限制
  │    - EmberKeeperAnimation 驱动原版灯芯的浮动、斗篷、脸部与提灯；EmberCharacterArt 提供共享精修部件
  │    - CameraFollow 平滑跟随玩家
  │
  ├─ 3. 战斗系统推进（EmberCombat.Tick）
  │    - 波次调度（EmberWaveDirector）：检查刷怪间隔，若配额未满，调用 EmberSpawnPlacement 在相机视口外沿带随机计算合法点生成怪物
  │    - 掉落物更新（EmberDrops）：推进地面药瓶与 Buff 道具的吸附距离、自动拾取与自然消失倒计时
  │    - 敌方弹幕推进：暗烛射手的暗弹与迟缓技能弹飞行位移
  │    - 敌人行为逻辑：各怪物执行各自的 IEnemyBehavior（直线追击、铁灯卫举盾阻挡、射手拉扯开火、引线虫自爆等）
  │    - 敌方伤害判定：敌人肉身接触撞击玩家、灼热精英光环烫伤、敌方弹幕命中玩家
  │    - 武器攻击（TickWeapons）：遍历已拥有的武器，依次执行自动索敌、冷却判定与弹道/AOE 生成
  │    - 共享火区（EmberBurnGround）：按固定帧率推进地面火海与持续伤害
  │    - 伤害统一判定（EmberCombatDamage）：把本帧武器造成的所有伤害扣除在怪物血量上
  │    - 集中死亡结算（ResolveDeaths）：
  │         * 判定怪是否触发“重生”词缀（是则读条复活，暂不计死亡）
  │         * 真正死亡：回收敌人、计入波次击杀、计算分裂怪母体、按概率生成治疗药瓶/增伤护符/疾行羽毛
  │    - 清波检测：场上敌人全清且本波刷怪配额用完，触发波次完成
  │         * Boss 波：预警后生成 Boss 与屏外伴随兵，存活时定时补缺；Boss 死亡即回收余兵并取消待分裂，阶段选卡或最终胜利
  │
  └─ 4. 数据推送与 UI 刷新
       - 将玩家血量、护盾、击杀数、当前波次文字推送给 HUD
       - 推进 Buff 状态环倒计时，更新角色头顶浮字的上浮与淡出
```

> **特别注意**：在第 3 步“战斗系统推进”中的任何一个关键节点（比如玩家掉血、清波切选卡），如果阶段不再是 `Playing`，代码会**立即中断本帧后续的战斗执行**，绝不会出现“玩家已经死了，同一帧内怪物还在打、子弹还在飞”的错乱现象。

## 4. 想加新东西怎么加？（照着抄的扩展 SOP）

游戏开发中最日常的事就是加内容。遵守以下流程扩展，绝不会破坏已有架构：

### 4.1 新增一把武器（4 步法）

1. **配身份**（`Assets/Scripts/Core/EmberWeaponCatalog.cs`）：
   在 `Catalog` 里加上新武器的 `Definition`，包含武器 ID（`EmberWeaponId` 增加枚举）、专属升级 ID、质变形态 ID、名字以及卡面描述文本。
2. **配参数**（`Assets/Scripts/Core/EmberWeaponTuning.cs`）：
   在 `EmberWeaponTuning` 中增加新武器的基础攻击力、攻速（冷却时间）、弹道速度、攻击范围，以及每级升级的提升增量。
3. **写逻辑**（在 `Assets/Scripts/Combat/Weapons/` 新建继承自 `EmberWeapon` 的类）：
   实现 `Tick(float dt, EmberWeaponContext context)`。需要找怪时调用 `context.FindNearestEnemy()`，需要发伤害调用 `context.ApplyDamage()`，需要播特效调用 `context.Effects`，需要播声音调用 `context.PlaySound()`。**严禁引用 `EmberGame`**。
4. **进工厂**（`Assets/Scripts/Combat/Weapons/EmberWeaponFactory.cs`）：
   在 `CreateAll()` 方法里把你的新武器 `new` 出来加进列表。完工！开局武器选择和局内抽卡就会自动出现新武器。

### 4.2 新增一个 Buff 效果（3 步法）

1. **声明配置**（`Assets/Scripts/Core/Buffs/EmberBuffCatalog.cs`）：
   新建一条不可变的 `BuffConfig`，填入 Buff ID、名称、持续秒数、移速乘区修正（`MoveSpeedMultiplier`）或全域伤害乘区修正（`DamageDealtMultiplier`）。
2. **挂载触发源**：
   - 如果是拾取物掉落触发：在 `EmberDrops.cs` 里的掉落列表和拾取判定加上新 Buff 的投递。
   - 如果是敌人技能附带：在敌方弹幕命中时调用 `host.TryAddBuff(newBuffConfig)`。
3. **绑定 HUD 图标**：
   打开 `Assets/UI/UIRoot.prefab`，在 `BuffHud` 下照着现有图标复制一个新的图标 Slot，将 ID 设为你新 Buff 的 ID。运行时拾取后就会自动出现图标、冷却倒计时环以及角色头顶的跳字。

### 4.3 新增一种怪物类型（3 步法）

1. **配血量与移速**（`Assets/Scripts/Core/LevelConfig.cs`）：
   在 `LevelConfig` 中为你新怪物配置随波次成长的基础生命公式与移动速度。
2. **写行为策略**（在 `Assets/Scripts/Combat/Enemies/` 下新建行为类）：
   实现 `IEnemyBehavior` 接口的 `Tick(EmberEnemyContext ctx, float dt)`。在里面编写它该怎么走位（追逐玩家/保持距离）和怎么开火攻击。
3. **注册兵种**（`Assets/Scripts/Combat/EmberEnemyRoster.cs`）：
   在怪物的生成枚举和对象池分配逻辑中加入该行为。波次控制器 `EmberWaveDirector` 即可在指定波次开始刷出该怪。

## 5. Unity 编辑器工具箱：什么时候点哪个按钮？

工程在顶部菜单 `Emberlight` 下提供了专门的辅助工具，遇到不同情况对号入座：

```text
Emberlight
  ├─ Bake Chinese font atlas                （烘焙中文字体静态图集）
  ├─ UI
  │    ├─ Repair UIRoot Images              （修复并保存 UIRoot 图片引用）
  │    ├─ Repair Selected Images            （修复选中物体的图片引用）
  │    ├─ Connect UIRoot Runtime            （为旧快照补齐控件并绑定主场景引用）
  │    └─ Update Buff HUD                   （重烘 Buff 文本并补齐 UIRoot 引用）
  ├─ Art
  │    ├─ Bake Classic Character Parts      （烘制原版造型的兜帽、衣褶、衣摆与灯壳图集）
  │    ├─ Build Hand Painted Sample         （一键装配手绘样板环境与 Prefab）
  │    ├─ Build Keeper Walk Prototype       （准备手绘拆件、关节 Prefab 与行走曲线）
  │    ├─ Use Keeper Walk Prototype         （切换使用手绘走路姿势原型）
  │    ├─ Use Original Keeper               （切换到第一版手绘整体贴图）
  │    ├─ Use Main Branch Characters        （恢复原版角色，保留新版环境、HUD 与 Buff 展示）
  │    ├─ Use Clean Toon Characters         （应用 A 清爽卡通玩家与普通怪小样）
  │    ├─ Build Player Sprite Animations     （导出两帧 Idle / Move 并原位绑定当前玩家 Prefab）
  │    ├─ Build Enemy Skins                 （导入无脚怪物皮肤并补齐现有敌人 Prefab 映射）
  │    ├─ Export Keeper Walk Frames         （导出行走透明序列帧）
  │    ├─ Reset Keeper Walk Curves          （恢复二维小样的默认动作曲线）
  │    ├─ Build Low Poly Prototype          （创建独立三维庭院与蒙皮角色）
  │    └─ Open Low Poly Courtyard           （保存当前编辑后打开 2.5D 小样）
  └─ Android
       ├─ 准备 APK 配置                      （配置 PlayerSettings、包名与横竖屏）
       ├─ 构建本地安装 APK                   （一键打出 Debug 测试包）
       └─ 构建自有签名 APK                   （打出 Release 发布包）
```

### 常见场景操作指南：

1. **场景里的 UI 图片丢了变成白块 / 紫块**：
   - **操作**：点击 `Emberlight → UI → Repair UIRoot Images`。
   - **原理**：工具会自动从 `Assets/Resources/Art/` 下把图集切片重新绑回 Prefab 的各个 Image 槽位上。
2. **代码里新加了中文文案，游戏运行时显示方框问号**：
   - **操作**：**必须先彻底关掉 Unity 编辑器**，在终端运行 `python Tools/atlas_glyph_check.py` 查缺口，然后运行烘焙批处理或打开 Unity 点击 `Emberlight → Bake Chinese font atlas`。
   - **注意**：静态图集不支持运行时动态加字。所有写在 C# 字符串里的汉字，必须经过烘焙进入图集。
3. **更换或重做手绘美术样板**：
   - **操作**：点击 `Emberlight → Art → Build Player Sprite Animations`，导出两帧 Idle / Move、持久切片、Clip 和 Controller，并原位连接现有玩家 Prefab。资源位于 `Assets/Art/CleanToonSample/Player`；原稿在其 `Source` 中，旧静态玩家保留为同级 Prefabs 目录的 KeeperStatic。日常修改帧图用 PNG，节奏用 Animation 窗口，移动/转向阈值与原图朝向用 Prefab。重复执行保留已有帧、Clip、Controller、切片身份和外观布局。
   - **运行**：`EmberKeeperMotion` 照常移动，`EmberKeeperAnimation` 根据根节点实际位移设置 `IsMoving` 和 `flipX`，只在 Playing 推进 Animator；停止进入 Idle，上下移动继续 Move 并保持水平朝向。两段 Clip 只切 Sprite，不写根位置、旋转或缩放，不影响攻击、碰撞与角色速度。
   - **怪物**：`Build Enemy Skins` 导入 `Assets/Art/CleanToonSample/Enemies` 的透明皮肤图，补齐现有 Shade Prefab 的 kind / Sprite / height 与独立盾图，保留已有映射。全部兵种和 Boss 使用无脚悬浮造型，复用浮动、压缩、翻转和预警；缺映射的旧模板继续回落原外观。
   - **其他入口**：`Use Clean Toon Characters` 应用当前玩家与敌人 Prefab；`Build Hand Painted Sample` 维护环境并保留角色选择与手动 HUD 布局；`Use Main Branch Characters` 可切回原版角色。均不回退 Buff 展示。分件与低模小样保留作对比。
4. **查看低模 2.5D 空间与角色步态**：
   - **操作**：点击 `Emberlight → Art → Open Low Poly Courtyard`，进入 Play，WASD / 方向键移动，空格暂停或恢复。

## 6. 自动化自检与打包交付

每次提交代码或导出工程前，在终端（PowerShell）中执行对应命令进行验证：

### 6.1 离线编译检查（无需等待 Unity 启动，几秒搞定）
```powershell
powershell -ExecutionPolicy Bypass -File Tools/compile-check.ps1
```
> **作用**：直接调用系统 Roslyn 编译器读取项目的 `.rsp` 文件编译 `Emberlight.Runtime`。写完代码顺手跑一下，有语法或引用错误秒级报错，不用卡顿切回 Unity 傻等编译。

### 6.2 跑自动化测试（先关闭 Unity 编辑器）
```powershell
# 1. 跑纯逻辑单测（EditMode：构筑、抽卡、品质、生命、Buff 等核心算法，数秒内跑完）
powershell -ExecutionPolicy Bypass -File Tools/run-tests.ps1 -Platform EditMode

# 2. 跑图形冒烟测试（PlayMode：带画面实机跑开局、战斗、升级弹窗与结算完整链路）
powershell -ExecutionPolicy Bypass -File Tools/run-tests.ps1 -Platform PlayMode
```

PlayMode 中的 `Assets/Tests/PlayMode/EmberArtSampleCapture.cs` 录制玩家移动、普通与密集战况；`Assets/Tests/PlayMode/EmberBossSwarmSmokeTests.cs` 输出兵种对照图和阶段/最终 Boss 群战，检查余兵退场与结算。图片、视频在 `Library/TestRun`，不是运行依赖，可通过上述测试重新生成。`Assets/Tests/PlayMode/EmberEnemyRenderingTests.cs` 另对实际渲染像素检查贴图、透明边缘、闪白、恢复与翻转，避免只检查资源字段而漏掉显示错误。

### 6.3 检查文档里的代码行号是否过期漂移
```powershell
powershell -ExecutionPolicy Bypass -File Tools/doc-line-check.ps1
# 若动了代码导致行号漂移，加 -Fix 自动修正：
powershell -ExecutionPolicy Bypass -File Tools/doc-line-check.ps1 -Fix
```

### 6.4 导出完整工程包
```powershell
powershell -ExecutionPolicy Bypass -File Tools/export-project.ps1 -Force
```
> **输出位置**：`Delivery/EmberlightWandere-project.zip`。<br>
> 导出的包内包含完整的 `Assets`（源码、测试、预制体、真实美术资源与 `.meta`）、`Packages`、`ProjectSettings`、`Tools`、`Docs` 与 `README`。打包脚本会自动拦截 Git LFS 指针占位虚假文件和缺少 `.meta` 的残缺资产，保证解压后重新导入即可直接开玩。

## 7. 常见踩坑排查清单（Troubleshooting）

| 异常现象 | 根本原因 | 解决办法 |
|---|---|---|
| 运行批处理脚本（如烘焙或打包）报错闪退 | 当前已有 Unity 编辑器实例开着，锁定了项目文件（`HandleProjectAlreadyOpenInAnotherInstance`） | **彻底关闭 Unity 编辑器**后再在终端运行命令行工具 |
| 新加了 WAV 音效文件，代码里调用了但在游戏里完全听不到 | 新拖入 Unity 的音频文件默认被设为 3D 音效且未预加载 | 选中音频文件，Inspector 中将 **3D Sound 取消勾选**（设为 2D），并勾选 **Preload Audio Data** |
| 重新导入图片后，UI 引用全部丢失变白块 | Unity 重新导入时把图集的 `spriteImportMode` 刷回了 `Default`，切片信息被洗掉了 | 检查对应图片的 `.meta`，切片权威由 `.meta` 保持；`Ember*ArtImporter` 会强制锁为 `Multiple` 模式，切勿手动改回 `Default` |
| 控制台警告 `The character used for Underline is not available` | TextMeshPro 给 UI label 赋值时会在字体里查找下划线 `U+005F` 和省略号 `U+2026`，静态字体库中缺失这两个字符 | 运行 `python Tools/atlas_glyph_check.py` 会自动检查这两个特殊字符，重新执行字体烘焙即可补全 |
| 用脚本修改含中文的 C# 代码文件后，Unity 报大量乱码语法错误 | Windows PowerShell 5.1 默认按系统 ANSI 编码读取了 UTF-8 无 BOM 的代码文件，回写时破坏了编码 | 严禁使用 `Get-Content` + `Set-Content` 改代码。改文件请用编辑器，或在脚本中显式指定 `[System.IO.File]::WriteAllText($path, $content, [System.Text.Encoding]::UTF8)` |
