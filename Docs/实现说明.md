# 实现说明

## 启动与单局

主场景入口为 `EmberGame`。`Awake` 创建本局状态、输入与选卡控制器；`Start` 装配战斗、菜单、相机与加载页，先隐藏场景中的 UIRoot。字体准备并继续后，通过 `EmberMenuUi.Bind` 绑定同一个 UIRoot 实例，玩家依次选择局长、难度、槽位数和一把起始武器。

`StartRunWith` 创建关卡配置、世界节点、特效与玩家，调用 `RunProgress.ConfigureRun` 配置构筑，重置生命与选卡状态，最后 `EmberCombat.Begin` 启动波次。只有 Playing 阶段推进计时、无敌帧、输入、移动、战斗与 HUD；中途阶段变化立即停止后续战斗推进。

## 主要调用链

| 功能 | 调用链与结果 |
|---|---|
| 移动 / 跟随 | `EmberInput` → `EmberKeeperMotion.Step`：键盘与摇杆向量合并、归一化限幅、边界钳制；`Follow` 更新相机 |
| 刷怪 / 追击 | `EmberWaveDirector.Tick` → `EmberEnemyRoster.Spawn` → `EmberSpawnPlacement.TryFind`：普通/遭遇怪从完整视口外沿带生成，成功才记配额；敌人按对应策略追击 |
| 自动攻击 | `EmberCombat.TickWeapons` → 各 `EmberWeapon.Tick` → context 选敌与投递伤害 → `EmberCombatDamage` |
| 死亡 / 掉落 | 死亡结算 → 计分、击杀与波次记录 → `EmberHealingDrops` 生成治疗物；拾取通过宿主请求 `Vitals.PickHealingDrop` |
| 受伤 | 宿主 → `EmberKeeperVitals.Hurt`：阶段 / 无敌帧检查 → 难度倍率 → 护盾 → 生命；调用方负责音效、HUD 与失败结算 |
| 选卡 | 清波 → `RunFlowController.OnWaveCleared` → `RunProgress.Choices` → 展示模型 / 面板 → `Choose`；新武器补偿一次、不连锁 |
| 范围伤害 | 火雨落点、环火接触、火海圈、共享燃地分别遍历目标并投递伤害；共享燃地不要求持有燃地武器 |

治疗掉落允许满血拾取，溢出丢弃，这是保留的当前实现。旧 M5 验收文档中的“满血不消耗”条目尚需裁定，不能把它算作已满足的需求。完整玩法与数值以 [requirements.md](requirements.md) 为准。

死亡统计修复：旧死亡结果只推进波次，整局 `Run.Kills` 未更新，HUD 始终显示 0；现通过已有宿主 `RegisterKill` 回报最终击杀，不改变计分与波次规则。图形回归测试在修复前检出了此问题。

选卡入口修复：`Choices` 成功生成候选后设置一次待选状态；刷新替换候选、不累加选择次数。此前只有手动调用 `OfferChoices` 的单元路径能提交，真实开局后的卡牌会被拒绝。新增 `RunProgressChoiceEntryTests` 已在修复前复现两条失败。

结算清理修复：结果页“返回营地”改为调用统一 `ReturnToCamp`，清理世界、战斗与本局状态；旧回调只显示菜单，留下仍处于 active 的已结束构筑。图形冒烟已在修复前检出该残留。

## 扩展位置

- 新武器：身份表增加定义和 ID，配置基础参数，实现 `EmberWeapon.Tick`，在工厂注册；再补构筑授予/升级、图标与行为测试。无需给武器传入 `EmberGame`。
- 调整卡池：修改 `EmberChoicePool`；调整构筑落地：修改 `RunProgress`。随机数调用顺序影响相同种子的复现，不能随意改动。
- 修改卡面：公共武器说明读 Catalog，其他词条读 `EmberCopy`，预览规则在 `EmberOfferPresentation`，布局在面板；改字后重烘字体。
- 新 buff/debuff：当前未建立通用状态模块，后续应先确定持续时间、叠加和移除规则，再接入伤害或移动入口。
