# 实现说明

本文面向接收工程和阅读源码的人，说明当前功能如何运行、从哪里进入代码，以及 UI 资源和工程如何维护。设计原因见 [技术分析](技术分析.md)，完整模块路由见 [架构总览](architecture/00-overview.md)。

## 打开工程与试玩

使用 Unity 2022.3.62f3 打开工程根目录，等待依赖和资源导入，打开 `Assets/Scenes/Emberlight.unity` 后运行。加载就绪后继续进入主菜单，依次选择局长、难度、槽位数和一把起始武器。WASD / 方向键或屏幕下半部虚拟摇杆移动，武器自动攻击；Esc 或暂停按钮打开设置。首次导入需要解析 Packages 中的依赖，环境说明见 [README](../README.md)。

## 启动与单局

主场景入口为 `EmberGame`。`Awake` 创建本局状态、输入与选卡控制器；`Start` 装配战斗、菜单、相机与加载页，先隐藏场景中的 UIRoot。字体准备后通过 `EmberMenuUi.Bind` 绑定同一个 UIRoot 实例，加载就绪并继续后进入主菜单。

玩家依次选择局长、难度、槽位数和一把起始武器。`StartRunWith` 创建关卡配置、世界节点、特效与玩家，配置构筑，重置生命与选卡状态，最后调用 `EmberCombat.Begin`。只有 Playing 阶段推进战斗；中途阶段变化立即停止本帧后续战斗处理。

```text
EmberGame.Update（Playing）
  → 本局计时、无敌帧计时、输入
  → 临时 Buff 计时、玩家移动与相机跟随
  → EmberCombat.Tick
      → 波次、治疗/Buff 掉落、敌方弹幕移动
      → 敌人行为与接触伤害、灼热光环
      → 武器与共享燃地、敌方弹幕命中
      → 死亡结算、分裂生成与清波判定
  → HUD 数据推送
```

输入和战斗中的关键调用后会复查阶段。暂停与选卡通过阶段门控停止战斗推进，加载页和面板动画可使用非缩放时间继续显示；恢复战斗应用保存的游戏倍速。

## 主要调用链

| 功能 | 调用链与结果 |
|---|---|
| 移动 / 跟随 | `EmberInput` → `EmberKeeperMotion.Step`：合并键盘与摇杆输入、限幅并钳制边界；`Follow` 更新相机 |
| 刷怪 / 追击 | `EmberWaveDirector.Tick` → `EmberEnemyRoster.Spawn` → `EmberSpawnPlacement.TryFind`：普通/遭遇怪从完整视口外沿带生成，成功才记配额；敌人按对应策略追击 |
| 自动攻击 | `EmberCombat.TickWeapons` → 各 `EmberWeapon.Tick` → context 选敌与投递伤害 → `EmberCombatDamage` |
| 死亡 / 拾取 | 最终死亡结算 → `EmberDrops` 独立判定治疗与 Buff 掉落 → 吸附拾取 → 宿主的生命结算或 Buff 添加入口；死亡同时更新击杀、波次与计分 |
| Buff / Debuff | 物品拾取或迟缓弹命中 → `TryAddBuff` → `Run.Buffs.Add`；Playing 时 `Tick`，移动和伤害入口读取倍率，HUD 读取只读列表 |
| 受伤 | `EmberKeeperVitals.Hurt`：阶段/无敌帧检查 → 难度倍率 → 护盾 → 生命；组合根将结果转成音效、HUD 与失败流程 |
| 选卡 | 清波 → `RunFlowController.OnWaveCleared` → `RunProgress.Choices` → 展示模型/面板 → `Choose`；新武器补偿一次、不连锁 |
| 范围伤害 | 火雨落点、环火接触、火海圈与共享燃地遍历目标并投递伤害；共享燃地不要求持有燃地武器 |

治疗掉落允许满血拾取，溢出治疗丢弃。Boss 与分裂子体保留特殊生成位置。完整玩法与数值见 [requirements.md](requirements.md)。

## 关键功能的实现位置

### 敌人死亡与物品拾取

武器通过 context 调用 `EmberCombatDamage.Apply` 扣血与标记死亡；所有武器推进后，`ResolveDeaths` 统一处理最终死亡。重生词缀接管时暂不掉落、不记击杀。最终死亡调用 `EmberDrops.OnDeath`，再回收敌人并返回击杀和 Boss 结果，由战斗根通知波次与宿主。

`EmberDrops.Tick` 管吸附和拾取。治疗物请求宿主的 `PickHealingDrop`，进入 `EmberKeeperVitals` 处理生命上限；增伤或疾行物请求 `TryAddBuff`，进入玩家 BuffManager。成功拾取或过期后回池；普通换波保留掉落，退出或新局清理。治疗与 Buff 独立判定，可同时掉落。

源码入口：[死亡结算](../Assets/Scripts/Combat/EmberCombatDamage.cs)、[治疗掉落](../Assets/Scripts/Combat/EmberDrops.cs)、[生命结算](../Assets/Scripts/Core/EmberKeeperVitals.cs)。

三类掉落物共用 `EmberPickupArt` 取图：治疗药瓶、增伤火种护符和疾行风羽。原图在 `Assets/Resources/Art/Pickups/ember-pickups.png`，切片保存在 `.meta`，由 `EmberPickupArtSetup.Configure` 配置；运行时加载持久 Sprite。素材和透明通道检查见 `Assets/Tests/EditMode/EmberPickupArtTests.cs`，来源见 [拾取物美术说明](reference/pickup-art.md)。

### Buff 对象与迟缓技能

`BuffConfig` 定义名称、属性修正和持续时间，`Buff` 保存本次剩余时间，`BuffManager` 负责同 Id 刷新、计时、移除与倍率汇总。玩家的管理器归 `EmberRunState.Buffs`，开局与回营地清空；选卡构筑继续归 RunProgress，不被临时增益改写。

暗烛射手周期性把下一次射击标记为迟缓技能，预警线与弹体同步变为青色。弹体命中时在扣血前记录无敌帧许可，随后请求施加迟缓；无敌、致死和拦截不会附加。弹体回池清除 Buff 引用。临时增伤在 `EmberCombatDamage.Apply` 统一应用，移动倍率在 `EmberKeeperMotion.Step` 读取。

效果和初值统一见需求 §4.10；维护契约见 [Buff 模块](architecture/10-buff-system.md)，源码入口为 `Assets/Scripts/Core/Buffs/`。增加同类属性效果时添加共享配置；计时与汇总逻辑无需复制。

`BuffManager.Add` 返回新增还是刷新，由组合根转给 HUD Presenter；`EmberBuffHud` 绑定 Prefab 图标槽位与浮字标签。环读取剩余时间比例，秒数向上取整且只在变化时更新；新增 / 刷新显示配置中的名称和百分比。Presenter 将相机与角色位置传入，浮字在角色上方使用非缩放时间上移淡出，同帧多次拾取复用不同标签。暂停、选卡或离开战斗清空浮字，Buff 本身仍按原生命周期处理。`Update Buff HUD` 负责一次性移除旧底板并迁移；日常布局直接编辑 Prefab，新增效果需增加同 Id 的图标槽位。

### 自动攻击、构筑与范围伤害

`EmberWeaponFactory.CreateAll` 创建六种武器实例；`Tick` 先检查本局是否拥有，再读取 `RunProgress` 的单武器强化与形态。冷却和选敌由武器负责，伤害统一投递给战斗模块。穿透火矢有静止开火门控，环火和燃地按各自接触、铺火规则工作，并非所有武器都需要主动锁定目标。

清波后 `RunFlowController` 决定选卡次数，`EmberChoicePool` 生成候选，`RunProgress.Choose` 应用构筑，面板只负责展示与回调。新武器补偿结束后再推进下一波。

火雨按落点和半径结算，环火遍历接触目标，`EmberBurnGround` 管共享火区的持续时间与伤害；其他武器生成火区时不要求玩家持有燃地武器。构筑加成保存在本局进度中，范围伤害保存在对应武器或共享效果中，二者分别推进。

源码入口：[武器注册](../Assets/Scripts/Combat/Weapons/EmberWeaponFactory.cs)、[共享燃地](../Assets/Scripts/Combat/EmberBurnGround.cs)、[选卡流程](../Assets/Scripts/Core/RunFlowController.cs)、[构筑状态](../Assets/Scripts/Core/RunProgress.cs)。

### 胜负、退出与重新开局

最终 Boss 死亡经波次控制器请求胜利；玩家生命归零进入失败。组合根停止战斗并展示结算。返回营地调用 `ReturnToCamp`，清理战斗、世界节点、输入和本局状态，保留场景 UI。

重新开局创建新的 `RunProgress` 与世界，`EmberCombat.Begin` 内先调用 `TearDown`，统一重置武器、火区、掉落与敌人等战斗状态，再绑定新局引用。地图配置先于边框创建应用，避免沿用上一局范围。装配入口见 [EmberGame](../Assets/Scripts/Core/EmberGame.cs)。

## UI 预制体与编辑器工具

场景的 `EmberGame.uiRoot` 引用 UIRoot 上的 `EmberUiRoot`，`introRoot` 引用 IntroRoot 上的 `EmberIntroView`。布局与静态图片保存在 Prefab 中，运行时更新文字、状态、回调和动态排卡。菜单、HUD、开局选择、设置与升级复用已有控件；加载页结束后隐藏实例。

对应资产为 `Assets/UI/UIRoot.prefab` 和 `Assets/UI/IntroRoot.prefab`。主场景已保存两个实例及引用；编辑布局后按需 Apply 回 Prefab。停止运行时主 UI 用于菜单预览，加载页可在 Prefab Mode 单独预览。这里的预制体化针对 UI，玩家、敌人和弹体等世界对象仍由代码与对象池创建。

`EmberFonts.ValidateBaked` 校验预烘字体，失败时回落动态图集。UI 与加载页均在字体准备后使用视图。修改布局可直接编辑 Prefab，日常调整无需重新运行连接工具。

- `Emberlight → UI → Repair UIRoot Images`：修复并保存 UIRoot 图片引用。
- `Emberlight → UI → Repair Selected Images`：修复选中对象的图片引用。
- `Emberlight → UI → Connect UIRoot Runtime`：为旧快照补齐静态控件并配置场景引用；操作后按需保存场景。
- `Emberlight → UI → Update Buff HUD`：重烘包含 Buff 名称的中文字体，补齐 UIRoot 的 Buff 文本引用；日常布局仍直接编辑 Prefab。

`Assets/UI/Generated` 及其 `.meta` 随工程提交。静态控件工厂与旧快照补建仅存在于 Editor；缺少运行时引用或控件容量不足会报告配置错误。

## 职责与扩展位置

- 新武器：在 `EmberWeaponCatalog` 增加身份定义，在 `EmberWeaponTuning` 配置参数，实现 `EmberWeapon.Tick`，最后在 `EmberWeaponFactory` 注册并接入构筑、说明和图标。
- 卡池与构筑：候选生成归 `EmberChoicePool`，状态落地归 `RunProgress`；随机数调用顺序影响相同种子的复现。
- 卡面：武器说明读 Catalog，其他文案读 `EmberCopy`；`EmberOfferPresentation` 生成展示数据，面板负责布局与交互。
- 共享燃地：`EmberBurnGround` 管理生命周期与伤害；武器经 context 投递燃地，战斗根统一推进与清理。
- HUD：条形值跟随状态，文字在对应值变化时格式化，时钟按显示秒更新；Stage 是波次文字的唯一写入点。
- Buff：共享配置归 EmberBuffCatalog，玩家生效对象归 BuffManager；HudReferences.Buffs 引用 EmberBuffHud，图标按 Id 绑定，环读取剩余比例，秒数变化时才更新文字；浮字使用独立的真实时间。

## 工程交付

使用 `Tools/export-project.ps1` 导出完整 Unity 工程与源码，默认输出 `Delivery/EmberlightWandere-project.zip`。包含 Assets、Packages、ProjectSettings、Tools、Docs 和根目录说明；Assets 内保留源码、测试、场景、预制体、实际资源与 `.meta`。脚本拒绝 LFS 指针占位资源和缺少 `.meta` 的资源文件，已有同名包时需明确使用 `-Force` 覆盖。

接收者解压后以包含 Assets、Packages、ProjectSettings 的目录作为工程根目录打开，首次导入重新生成 Library。交付前应在独立目录重新导入并运行主场景，确认不依赖原工程缓存或本机路径；导出成功本身不能证明重新导入成功。修改工程后重新导出最新包，不能只提交可执行程序。
