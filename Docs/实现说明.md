# 《烬灯行者》实现说明

## 项目模块

1. **[玩家操作与生命](#module-1)**：读取移动输入，更新角色位置，处理生命、护盾、无敌帧与治疗。
2. **[构筑与选卡](#module-2)**：记录已获得的武器和升级，生成候选卡，应用选择结果并安排补偿选卡。
3. **[武器与伤害](#module-3)**：更新六种武器的状态，判定命中，结算伤害并维护共享燃地。
4. **[敌人与波次](#module-4)**：安排刷怪，管理敌人列表，执行普通敌人与 Boss 的行为，处理死亡、掉落与清波。
5. **[Buff](#module-5)**：记录临时增益和减益的生效实例、剩余时间与属性修正。
6. **[界面、画面与声音](#module-6)**：显示菜单、HUD 和卡片，驱动角色动画，管理图集、字体、特效与音频。
7. **[单局流程与配置](#module-7)**：装配上述模块，管理启动、开局、暂停、选卡、结算和返回流程，并提供本局配置。

一次火球攻击由几个模块共同完成：武器模块读取构筑数据，选定目标后发射火球；命中后结算伤害，敌人死亡后处理击杀与掉落，HUD 显示本局状态变化，音频模块播放对应音效。这些环节由 `EmberGame` 和 `EmberCombat` 组织调用。

主场景是 `Assets/Scenes/Emberlight.unity`，入口组件是 `EmberGame`。启动和每帧更新的顺序见第七节。

## 一、玩家操作与生命

主要脚本：`EmberInput.cs`、`EmberKeeperMotion.cs`、`EmberKeeperVitals.cs`、`EmberVitalOutcome.cs`。

### 输入与移动

`EmberInput` 保存当前拖动的指针、按下位置 `origin` 和摇杆向量 `stick`。`Tick` 读取触摸或鼠标输入：在移动区域按下时记录起点，用拖动距离除以摇杆半径得到 `stick`，再限制向量长度；松开时清空输入。摇杆显示和按 Esc 暂停由 `Presenter` 提供的回调处理。

`EmberGame.Update` 读取输入后，调用 `EmberKeeperMotion.Step` 并传入 `Stick`。`Step` 将键盘 `Horizontal`、`Vertical` 轴组成的向量与摇杆向量相加，再将结果的最大长度限制为 1，避免斜向移动或两种输入同时生效时速度叠加。

位移按「移动向量 × `PlayerSpeed` × Buff 移速倍率 × `dt`」计算，移动后通过 `EmberWorld.Clamp` 将位置限制在地图范围内。`Follow` 让相机的 X、Y 坐标跟随角色，Z 坐标保持固定偏移。角色动画根据实际位移更新，见第六节。

### 受伤结算

`EmberKeeperVitals` 保存当前生命 `Health` 和无敌帧剩余时间 `HurtTimer`。构造时传入三个查询回调，分别读取当前构筑、难度伤害倍率和游戏阶段；UI 与音效由 `EmberGame` 处理。

战斗代码调用 `EmberGame.HurtPlayer` 后，依次执行：

1. `Vitals.Hurt` 检查当前阶段、无敌帧和伤害值，不满足条件时直接返回。
2. 将伤害乘以本局难度倍率，再交给 `RunProgress.AbsorbDamage`。
3. `AbsorbDamage` 先消耗 `Shield`，再返回未被护盾吸收的伤害。
4. `Vitals` 从当前生命中扣除剩余伤害，并开始新的无敌帧。
5. `EmberGame` 根据结算结果播放受伤反馈、刷新 HUD，再由 `CommitHealthChange` 判断是否进入失败结算。

护盾吸收全部伤害时，生命不变，但仍会触发无敌帧。`EmberVitalOutcome` 用三个值区分结果：`Rejected` 表示本次调用被拒绝，`NoChange` 表示已结算但生命未变，`Changed` 表示生命发生变化。

### 治疗和护盾显示

`Heal` 要求角色处于战斗阶段且未满血。治疗掉落使用 `PickHealingDrop`，允许角色满血时拾取，超出生命上限的治疗量直接丢弃；拾取成功后回收掉落物。

`RunProgress` 保存当前护盾值 `Shield`，以及本局累计获得的护盾量 `ShieldCapacity`。`EmberHud` 读取这两个值绘制独立护盾条，护盾耗尽时置灰，再次获得护盾后恢复配色。

## 二、构筑与选卡

主要脚本：`EmberWeaponCatalog.cs`、`EmberRarity.cs`、`RunProgress.cs`、`EmberChoicePool.cs`、`RunFlowController.cs`。共享武器参数保存在 `EmberWeaponTuning.cs` 中。

### 构筑数据

`EmberWeaponCatalog` 定义武器、词条、专属和质变的 Id，以及它们之间的归属关系。`EmberRarity.cs` 包含品质工具和候选卡数据 `EmberOffer`。每张候选卡保存 `Id`、`Rarity` 和 `WeaponId`；攻击力和攻速卡通过 `WeaponId` 指定作用武器。

`RunProgress` 保存本局可变数据：

- `ownedWeapons`、`metamorphs`、`exclusives` 分别记录已获得的武器、质变和专属。
- `weaponMagnitude`、`weaponAttackSpeed` 按武器 Id 保存攻击力和攻速升级。
- `WeaponSlots` 与 `CoreWeaponId` 记录槽位数和起始武器，其他数据包括护盾、幸运、增幅、分数和刷新次数。

`StartRun` 创建新的 `RunProgress`，`ConfigureRun` 校验输入并设置起始武器。正式菜单只传入一把起始武器，其余槽位在局内逐步补齐。

例如，选择「火球攻击力」后，`Choose` 会增加 `weaponMagnitude` 中火球对应的数值，下次发射火球时再读取。各武器分别保存自己的攻击力和攻速升级。

### 候选生成与提交

`RunProgress.Choices` 调用 `EmberChoicePool.Build` 生成候选，并将本次选择标记为待处理。卡池根据已有武器、空槽、幸运，以及 `CanExclusive`、`CanMetamorph` 的结果筛选卡牌并抽取品质。候选张数由 `ExpectedCount` 计算；存在空槽时，会增加新武器候选。

卡池以 `(Id, WeaponId)` 去重，保证同一武器的同一词条在同屏只出现一次。玩家点击卡牌后，`RunFlowController.IsCurrentlyOffered` 检查其 `(Id, Rarity, WeaponId)` 是否与当前候选完全一致，品质也必须匹配。

校验通过后，`RunProgress.Choose` 按卡牌类型更新属性，或授予武器、专属、质变，并完成本次待选卡的结算。卡面预览只读取构筑数据。

### 清波奖励与补偿选卡

清波后，`EmberGame.OnWaveCleared` 将选卡流程交给 `RunFlowController`：

1. 从 `LevelConfig.PicksAfterWave` 取得本轮计划选卡次数，保存在 `pendingPicks` 中。
2. 调用 `RequestChoices` 生成候选，再通过 `OnUpgradeOffered` 通知 `EmberGame` 切换阶段并显示面板。
3. 完成一次计划内选卡后，减少剩余计划次数。如果本次选择获得了一把尚未拥有的武器，则将 `compensationPick` 设为 `true`，立即补发一次选卡。
4. 补偿选卡不消耗计划次数，也不会再次触发补偿。补偿结束后，根据剩余次数决定继续选卡，还是结束本轮选卡流程。
5. 全部选卡结束后，`EmberGame` 调用 `combat.AdvanceAfterUpgrade`，再恢复到 `Playing` 阶段。

`TryRefresh` 要求当前处于选卡阶段、存在待选卡且还有刷新次数。刷新只替换当前候选，不增加待选卡计数 `Pending`。

## 三、武器与伤害

每种武器保存各自的冷却、弹体或视图数据。`EmberCombat` 按顺序调用武器的 `Tick`，并提供敌人查询、伤害结算、对象池、特效和音效回调。

武器接口和创建入口分别在 `EmberWeapon.cs`、`EmberWeaponFactory.cs` 中，伤害结算与燃地管理分别在 `EmberCombatDamage.cs`、`EmberBurnGround.cs` 中。

### 武器接口

`EmberWeapon` 定义 `Tick` 与 `Reset`。`EmberWeaponFactory.CreateAll` 创建六种武器的实例，列表顺序决定每帧的更新顺序。

开局时，`EmberCombat` 将世界、玩家、相机、对象池、特效，以及敌人查询和伤害回调写入 `EmberWeaponContext`；每帧再更新 `Progress`、`Elapsed` 和实际移动速度 `PlayerSpeed`。各武器通过这个上下文对象访问战斗数据。

火球通过 `FindNearestVisibleEnemy` 查找目标，命中后调用 `DealDamage`，弹体视图通过 `Pool` 获取和归还。接触伤害通过 `DealContactDamage` 结算，音效通过 `PlaySound` 播放。

### 六把武器

- **火球**（`EmberBasicShotWeapon.cs`）：保存 `fireTimer` 和 `Shot` 列表。冷却结束后寻找最近的可见敌人，创建记录速度、寿命和发射时伤害值的弹体。每帧移动弹体并检查可见范围和命中，命中或到期后回收；质变后的命中还会请求创建共享燃地。
- **环火**（`EmberOrbitWeapon.cs`）：保存环绕球视图和燃地生成间隔。按本局数量补齐视图，用累计时间计算各球围绕玩家的位置。对每个敌人，每帧只取距离最近且与其接触的环绕球结算伤害，避免多球伤害叠加；质变后会沿轨迹留下火区。
- **燃地**（`EmberTrailWeapon.cs`）：按间隔在玩家位置请求创建火区；火环形态还会维护 `ringView`，使其跟随玩家并结算范围内的接触伤害。火区本身由 `EmberBurnGround` 管理。
- **穿透火矢**（`EmberPierceWeapon.cs`）：每支 `Arrow` 记录剩余命中次数、已命中敌人集合和分裂标记 `isSplit`。角色接近静止时才发射新箭，开始移动后，已发出的箭仍继续飞行。质变后的命中会产生分裂箭，分裂箭不会再次分裂。
- **回旋烬蝶**（`EmberBoomerangWeapon.cs`）：每只 `Butterfly` 保存方向、行进距离、返程状态、剩余往返次数，以及去程和返程各自的命中集合。飞到指定距离后，烬蝶转而追向玩家当前位置；完成一次往返后，再决定重新出发或回收。
- **天降火雨**（`EmberMeteorWeapon.cs`）：将目标当时的位置保存为 `Strike.point`，同时记录倒计时、半径、伤害和预警圈。倒计时结束后，在已保存的落点结算范围伤害并回收预警圈；预警期间落点保持不变。

火球在发射时按「基础伤害 × `DamageMul` × 单武器攻击力倍率 × 形态倍率」计算伤害，并将结果保存在弹体中。实际命中时，再乘以当前临时 Buff 的增伤倍率。

### 命中与扣血

`EmberCombatDamage.Apply` 根据下标取得敌人，检查目标能否选中、是否位于伤害判定视口内。检查通过后，依次处理：

1. 将伤害乘以玩家当前的 `BuffManager.DamageMultiplier`。
2. 如果目标是铁灯卫，再根据伤害来源方向计算正面减伤。
3. 扣除敌人生命，更新血条和受击反馈。
4. 生命归零时，先检查重生词缀能否阻止本次死亡；未触发重生时，再调用行为的 `OnLethal` 处理致死伤害。
5. 如果上述处理都未阻止死亡，则将 `dead` 设为 `true`，等待武器更新结束后统一处理死亡。

敌人被标记为 `dead` 后，会等到全部武器的 `Tick` 完成才从名册移除，避免改变其他武器正在使用的敌人下标。

### 共享燃地

`EmberBurnGround` 保存 `Flame` 列表，每个火区记录视图、寿命和强度系数 `powerScale`。达到容量上限时替换最早创建的火区，到期后回收视图并复用逻辑对象。火球、环火和燃地武器都可以调用 `SpawnPatch`，玩家没有燃地武器时也能产生火区。

`EmberCombat` 更新 `EmberTrailWeapon` 时，也会调用火区的 `Tick`。火球和环火排在它之前更新，因此它们在本帧创建的火区也能参与当帧结算。火区的 `Tick` 读取当前构筑，按范围和 `dt` 计算接触伤害，再交给统一的伤害入口。

## 四、敌人与波次

主要脚本：`EmberCombat.cs`、`EmberWaveDirector.cs`、`EmberEnemyRoster.cs`、`EmberEnemy.cs`、`EmberSpawnPlacement.cs`、`EmberPool.cs`。战斗模块通过 `IEmberCombatHost.cs` 定义的接口读取阶段、构筑和计时，并请求受伤、拾取或流程切换。

### 刷怪与敌人创建

`EmberWaveDirector` 保存波次编号 `wave`、生成配额 `waveQuota`、已生成数 `waveSpawned`、已击杀数 `waveKilled`、额外生成数 `extraSpawned`，以及倒计时和待选卡标记 `awaitingUpgrade`。`StartWave` 根据 `LevelConfig` 判断本波是普通波还是 Boss 波，重置计数，并设置横幅、生成间隔或 Boss 预警。

普通波的 `Tick` 检查生成配额、同屏上限和生成间隔，满足条件后调用 `Host` 的生成方法。`EmberCombat` 实现了这个 `Host` 接口，并将创建工作交给敌人名册。只有生成成功才增加 `waveSpawned`；找不到合法落点时，保留本次配额供后续生成。遭遇事件也使用同一组生成方法。

`EmberEnemyRoster` 先确定敌人种类，再通过 `EmberSpawnPlacement` 查找地图范围内、完整相机视口外的落点。随后从对象池获取视图，创建 `EmberEnemy`，设置生命、速度、词缀、行为、皮肤和血条，最后加入名册。Boss 使用玩家附近的指定落点；分裂子体则允许在母体附近的屏内位置生成。

`EmberPool` 用字典保存不同 `key` 对应的对象栈，取用时优先复用已有对象。回收敌人时还会清理血条和附加的表现对象，避免下次取用时残留上一种外观。

### 敌人行为与 Boss 招式

`EmberEnemyBehavior.cs` 定义行为接口 `IEnemyBehavior`、上下文和具体行为。`CreateBehavior` 根据敌人种类 `kind` 选择实现：

- `ChaseBehavior`：控制基础追击。
- `ShooterBehavior`：根据距离控制蓄力、射击和技能弹。
- `SplitBehavior`：在死亡回调中记录分裂位置。
- `ShieldBehavior`：处理盾牌朝向及正面减伤规则。
- `BomberBehavior`：接近玩家后引爆，并处理致死伤害下的引爆行为。

`EmberEnemy` 保存生命、视图、半径、词缀和行为等运行时数据。`TickEnemies` 遍历名册，更新受击闪白和重生相关状态。带有 Boss AI 的敌人调用 `ai.Tick`，其他敌人执行普通行为；之后再检查接触伤害和灼热范围伤害。

`EmberBoss.cs` 通过 `AttackState` 管理追击、冲锋预警、冲锋、爆发预警、齐射预警和恢复。Boss 的行为同样在遍历名册时更新，暗弹的移动与命中则由 `EmberEnemyProjectiles.cs` 管理。带减益效果的技能通过宿主施加伤害和 Buff。

`EmberEnemyVisual.cs`、`EmberEnemySilhouette.cs` 根据敌人状态更新皮肤、漂浮动画和攻击预警。

### 死亡、分裂与掉落

全部武器更新后，`EmberCombatDamage.ResolveDeaths` 倒序处理已标记为 `dead` 的敌人：必要时检查是否触发重生，再调用 `OnDeath`、生成掉落、回收视图并将敌人移出名册。处理结果包含击杀数和 Boss 是否死亡。

`EmberCombat` 根据结果更新本局击杀数和波次计数。分裂请求先保存在 `pendingBroods` 中，待死亡处理完成后再创建子体，并增加 `extraSpawned`，避免在命中遍历期间向名册添加敌人。

烬胎母体有两处代码会记录分裂请求：`SplitBehavior.OnDeath` 和死亡结算器中按 `kind` 判断的分支。最终子体数量由这两处请求共同决定。

`EmberDrops.cs` 保存每个掉落物的视图、寿命和可选的 Buff 配置。敌人死亡时，分别判断是否掉落治疗物品或 Buff。`Tick` 更新掉落物的剩余寿命和吸附移动，接近玩家后请求宿主治疗或施加效果；宿主接受请求后，才回收掉落物。分裂子体不会再次产生这些掉落。

### 清波与 Boss 结束

普通波清波需要同时满足三个条件：配额内的敌人已全部生成、场上没有敌人、尚未进入待选卡状态。清波后清除暗弹，并通知选卡流程。

Boss 波在预警开始时就会设置 Boss 波标记，避免将预警期间的空场误判为清波。预警结束后创建 Boss 与伴随兵，后续再按目标数量补兵。

Boss 死亡后，取消尚未处理的分裂请求，让剩余敌人退场，并移除玩家当前的迟缓效果。退场敌人不计入击杀，也不额外产生掉落。阶段 Boss 死亡后进入选卡流程，最终 Boss 死亡后进入胜利结算。

## 五、Buff

主要脚本：`BuffConfig.cs`、`Buff.cs`、`BuffManager.cs`、`EmberBuffCatalog.cs`。

### 配置、实例与管理器

`BuffConfig` 保存可供多个角色共用的效果配置，创建后不再修改。配置包括 Id、名称、作用属性、修正量、持续时间和是否为减益。

`Buff` 表示某个角色身上正在生效的一项效果，保存配置引用 `Config` 和独立的剩余时间 `Remaining`。`BuffManager` 保存 `active` 列表，通过只读集合公开当前效果，并汇总移动速度和伤害倍率。

`EmberBuffCatalog` 提供增伤、疾行和迟缓的共享配置。不同角色使用同一份配置时，各自持有独立的实例和倒计时。

### 新增、刷新与到期

1. 掉落或技能通过 `EmberGame.TryAddBuff` 请求添加效果，入口先检查当前阶段和本局是否有效。
2. `BuffManager.Add` 查找同 Id 的效果；不存在时创建实例并重新汇总属性，已存在时刷新 `Remaining`，不叠加实例。
3. 同 Id 的效果必须使用同一个配置对象，否则抛出参数异常，避免同名效果使用不同规则。
4. `EmberGame` 只在 `Playing` 阶段调用 `Buffs.Tick`。到期实例移除后，重新汇总属性。
5. 移动和伤害模块读取最新倍率，界面读取配置与剩余时间。

`Add` 返回 `true` 表示新增，返回 `false` 表示刷新。两种情况都会更新 HUD 反馈，`EmberGame.TryAddBuff` 均返回成功，触发本次效果的掉落物随后回收。

### 属性汇总

`Recalculate` 从基础倍率开始，累加仍在生效的同属性 `Bonus`，再确保结果不低于设定下限。效果到期后重新计算倍率，基础移速和武器伤害本身保持不变。

`EmberKeeperMotion.Step` 读取 `MoveSpeedMultiplier`。弹体、环绕球接触和共享燃地的伤害统一经过 `EmberCombatDamage.Apply`，在实际结算时读取 `DamageMultiplier`。

## 六、界面、画面与声音

### UI 绑定与操作回调

`EmberUiRoot.cs`、`EmberIntroView.cs` 保存控件引用，主场景通过 `Assets/UI/UIRoot.prefab`、`Assets/UI/IntroRoot.prefab` 接入对应界面。布局、图片、字号和静态层级保存在 Prefab 中。

`EmberGame.Start` 调用 `EmberIntro.cs` 准备字体并显示加载页。字体准备完成后，`EmberGame` 调用 `EmberMenuUi.Bind` 绑定界面，并创建 HUD Presenter，随后等待玩家点击或按键进入菜单。

`EmberMenuFlow.cs` 保存玩家选择的征程、难度和槽位，最后将起始武器传给宿主的 `StartRun`。`EmberMenuUi.cs` 绑定通用面板和按钮，界面通过 `IEmberMenuHost` 请求切换阶段或开始新局。

`EmberHudPresenter.cs` 读取本局状态、构筑数据、波次和 Boss 信息，再交给 `EmberHud.cs` 显示。条形控件随数值变化更新，文字和阶段信息在对应数据变化时刷新；受伤、拾取和选卡完成后，也会主动调用 `Push` 刷新 HUD。

`EmberOfferPresentation.cs` 生成卡牌的 `Title`、`Description`、`NumericPreview` 和 `Badge`。`EmberUpgradePanel.cs` 用这些内容填充候选卡，调整排布并绑定选择、刷新回调；`EmberCardMotion.cs` 负责卡牌动画。玩家确认选择后，再由 `RunProgress` 更新构筑。

### Buff 显示、设置与安全区

`EmberBuffPresentation.cs` 根据效果定义生成说明，`EmberBuffHud.cs` 按 Id 绑定图标、计时环和秒数，并复用浮字槽位。HUD Presenter 传入当前效果集合 `Active` 和角色位置，效果计时仍由 `BuffManager` 推进。

`EmberSettingsPanel.cs` 读取音量和 `GameSpeed`，通过按钮与滑条修改对应设置。继续游戏或返回营地时，执行外部传入的回调。`EmberSafeAreaWatcher.cs` 检查屏幕安全区和分辨率，只在变化时通知界面重新布局。

### 角色与场景外观

`Assets/Art/HandPaintedSample/ArtSet.asset` 通过 `EmberArtSet.cs` 提供玩家、敌人和庭院模板。开局时实例化玩家和庭院，敌人生成时再使用敌人模板；玩家模板为空时，创建原版外观。

当前玩家的序列帧和动画位于 `Assets/Art/CleanToonSample/Player`，角色模板位于 `Assets/Art/CleanToonSample/Prefabs`，敌人皮肤和盾牌图片位于 `Assets/Art/CleanToonSample/Enemies`。项目中还保留了原版角色和手绘分件角色。

`EmberKeeperAnimation.cs` 在 `LateUpdate` 中根据实际位移计算速度，设置 Animator 的 `IsMoving` 参数，并结合横向速度和默认朝向控制 `flipX`。Animator 的 `speed` 平时保持为 0，由组件在 `Playing` 阶段手动调用 `Update` 推进动画。序列帧模式用帧图表现动作，保留角色图原有的位置、倾斜和缩放。

`EmberKeeperRig.cs` 驱动分件动画，角色根节点的移动由 `EmberKeeperMotion` 负责。`EmberEffects.cs` 管理粒子，根据外部传入的阶段查询回调决定是否更新。

### 图集、字体与音频

`EmberWorldArt`、`EmberUiArt`、`EmberCardIcons`、`EmberCardFrames`、`EmberPickupArt` 分别读取场景、UI、卡牌和拾取物资源。`EmberBakedArt` 优先加载预烘焙的图元图片；加载失败时，由 `EmberArt` 等类生成图形。切片标识和导入设置保存在 `.meta` 文件中。

`EmberFonts.cs` 检查预烘焙的 TMP 字体，通过 `ValidateBaked` 校验后才交给 UI 使用；字体缺失或校验失败时，改用动态字体。`EmberCopy.cs`、武器文案和效果名称共同决定需要覆盖哪些字形。

`EmberAudio.cs` 创建音乐和音效使用的 `AudioSource`，通过 `Resources` 加载素材，分别管理两类音量并保存到 `PlayerPrefs`。音乐随菜单和战斗切换，密集音效通过非缩放时间限制播放频率。素材缺失时输出警告，并跳过播放。

## 七、单局流程与配置

主要脚本：`EmberGame.cs`、`EmberRunState.cs`、`EmberRunPhase.cs`、`IEmberRunPhaseSource.cs`、`LevelConfig.cs`、`GameSpeed.cs`。

### 启动与开局

场景中的 `EmberGame` 负责初始化和每帧调用。`Awake` 创建 `EmberRunState`、`RunFlowController` 和 `EmberInput`；`Start` 初始化音频、相机、战斗、菜单和加载页。加载页就绪且玩家确认继续后，进入菜单。

`EmberRunState` 保存构筑、配置、生命、Buff、计时、击杀数，以及 `World`、`Keeper`、`Cam`、`Effects` 等场景对象引用。生命结算、升级和选卡规则由各自对应的对象处理。

菜单完成选择后，调用 `StartRun` 开始新局：

1. 检查 UI 和 `ArtSet`，按玩家选择创建 `LevelConfig`，并重置选卡流程。
2. 停用并销毁旧世界，再创建新的 `World` 和 `Effects`。
3. 创建新的 `RunProgress`，清空 Buff 和击杀数，重置生命。
4. 实例化庭院与玩家，并为外观组件传入阶段查询回调。
5. 应用地图配置，调用 `combat.Begin`，为敌人名册、对象池、波次和武器模块绑定本局数据。
6. 将相机对齐玩家，再调用 `SetPlaying` 收起面板、应用倍速并显示 HUD。

### 每帧更新顺序

`EmberGame.Update` 只在 `Playing` 阶段推进本局逻辑。先累计本局时间、更新无敌帧并读取输入；确认仍处于战斗阶段后，依次更新 Buff、玩家移动、相机和战斗，最后刷新浮字反馈与 HUD。

`EmberCombat.Tick` 先更新波次和掉落，再移动暗弹、执行敌人行为并检查接触伤害，随后处理灼热范围伤害、武器和共享燃地，最后检查暗弹命中、处理敌人死亡并判断是否清波。

输入可能触发暂停，受伤可能结束本局，因此更新过程中会再次检查阶段。角色外观、粒子、安全区和界面动画则在各自的 Unity 回调中更新。

### 暂停、结算与返回

`Pause` 将阶段设为 `Paused`，清空拖动输入，隐藏 HUD 和摇杆，并打开设置页。点击「继续」后调用 `SetPlaying` 恢复战斗。本局逻辑、角色动画和粒子都会检查阶段，暂停时停止更新；`Time.timeScale` 仍保持玩家选择的倍速。卡牌动画、加载页和音效播放频率控制使用非缩放时间。

`EndRun` 将阶段设为 `Won` 或 `Lost`，播放菜单音乐并显示统计，同时保留本局世界。结算页的「重新开始」进入选局流程，「返回营地」调用 `ReturnToCamp`。

`ReturnToCamp` 恢复基础 `timeScale`，清空输入状态和选卡流程，并隐藏面板。接着调用 `combat.TearDown` 清理战斗对象，再销毁 `World`，通过 `Run.Clear` 清除本局数据和场景引用，最后显示菜单。场景中的 UI 对象保留，供下一局继续使用。

### 配置与倍速

`LevelConfig` 保存难度、地图、波次、敌人、Boss、遭遇和掉落配置。`Create` 根据玩家选择生成本局配置，战斗模块通过 `QuotaForWave`、`SpawnInterval`、`TrashHp` 等方法读取所需数值。`ApplyWorld` 将地图边界写入 `EmberWorld.Limit`。

`EmberWeaponTuning` 保存武器基础参数和共享升级增量，供构筑、攻击和卡面预览共同使用。

`GameSpeed` 将玩家选择的倍率保存到 `PlayerPrefs`，并应用到 `Time.timeScale`。`SetPlaying` 会再次调用 `Apply`，确保返回流程重置时间倍率后，仍能恢复玩家的选择。
