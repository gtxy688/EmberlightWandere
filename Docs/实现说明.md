# 《烬灯行者》实现说明

## 项目模块

1. **[玩家操作与生命](#module-1)**：读取移动输入，更新角色位置，处理生命、护盾、无敌帧与治疗。
2. **[构筑与选卡](#module-2)**：保存已获得武器和升级，生成候选卡，提交选择并安排补偿选卡。
3. **[武器与伤害](#module-3)**：推进六把武器，检查命中，结算敌人伤害与共享燃地。
4. **[敌人与波次](#module-4)**：安排刷怪，持有敌人，推进兵种和 Boss 行为，处理死亡、掉落与清波。
5. **[Buff](#module-5)**：管理临时增益和减益的实例、时间与属性修正。
6. **[界面画面与声音](#module-6)**：显示菜单、HUD 和卡片，连接角色动画、图集、字体、特效与音频。
7. **[单局流程与配置](#module-7)**：连接上述系统，管理启动、开局、暂停、选卡、结算、返回与配置。

火球攻击涉及几个模块：武器读取构筑数据、选择目标并发射；命中后由伤害代码扣血，战斗代码处理死亡，HUD 和音效更新反馈。执行顺序由 EmberGame 和 EmberCombat 控制。

主场景是 `Assets/Scenes/Emberlight.unity`，入口组件是 EmberGame。启动和每帧更新的顺序见第七节。

## 一、玩家操作与生命

主要脚本：`EmberInput.cs`、`EmberKeeperMotion.cs`、`EmberKeeperVitals.cs`、`EmberVitalOutcome.cs`。

### 输入与移动

EmberInput 保存拖动指针、按下位置 origin 和摇杆向量 stick。Tick 读取触摸或鼠标输入，在移动区域按下时记录起点，用拖动距离除以摇杆半径得到 stick，并限制其长度。松开时清空输入。摇杆显示和 Esc 暂停分别通过 Presenter 的回调处理。

EmberGame.Update 读取输入后调用 EmberKeeperMotion.Step，传入 Stick。Step 将键盘 Horizontal／Vertical 与摇杆向量相加，并将结果限制到单位长度，防止斜向移动或同时使用两种输入时速度叠加。

位移按“移动方向 × PlayerSpeed × Buff 移速倍率 × dt”计算，移动后用 EmberWorld.Clamp 限制位置。Follow 让相机的 X、Y 跟随角色，Z 保持固定偏移。角色动画根据实际位移更新，见第六节。

### 受伤结算

EmberKeeperVitals 保存 Health 和 HurtTimer。构造时传入的函数用于读取当前构筑、难度伤害倍率和阶段；UI 与音效由 EmberGame 处理。

战斗代码调用 EmberGame.HurtPlayer 后，依次执行：

1. Vitals.Hurt 拒绝非 Playing、仍在无敌帧或伤害无效的调用。
2. 伤害乘本局难度倍率，再交给 RunProgress.AbsorbDamage。
3. AbsorbDamage 先消耗 Shield，返回仍需扣生命的余量。
4. Vitals 扣除余量，并开始新的无敌帧。
5. EmberGame 接收结果，播放受伤反馈、刷新 HUD，由 CommitHealthChange 判断是否进入失败结算。

护盾吸收全部伤害时，生命不变，但仍会触发无敌帧。EmberVitalOutcome 的 Rejected 表示本次调用被拒绝，NoChange 表示已结算但生命未变，Changed 表示生命发生变化。

### 治疗和护盾显示

Heal 要求角色正在战斗且未满血。治疗掉落调用 PickHealingDrop，允许满血拾取，超出生命上限的治疗量丢弃；拾取成功后掉落物回收。

护盾值 Shield 与累计容量 ShieldCapacity 保存在 RunProgress。EmberHud 读取二者绘制独立护盾条，耗尽时置灰，补充后恢复。

## 二、构筑与选卡

主要脚本：`EmberWeaponCatalog.cs`、`EmberRarity.cs`、`RunProgress.cs`、`EmberChoicePool.cs`、`RunFlowController.cs`。共享武器参数在 `EmberWeaponTuning.cs`。

### 构筑数据

EmberWeaponCatalog 定义武器、词条、专属和质变的 Id 及归属。EmberRarity.cs 包含品质工具和 EmberOffer。每张候选卡保存 Id、Rarity 和 WeaponId；攻击力、攻速卡用 WeaponId 指定作用武器。

RunProgress 保存本局可变数据：

- ownedWeapons、metamorphs、exclusives 记录已获得内容。
- weaponMagnitude、weaponAttackSpeed 按武器 Id 保存攻击力和攻速升级。
- WeaponSlots 与 CoreWeaponId 记录槽位及起始武器，另保存护盾、幸运、增幅、分数和刷新次数。

StartRun 创建新的 RunProgress，ConfigureRun 校验输入并建立起始武器；正式菜单只提交一把，其余槽位在局内补齐。

选择“火球攻击力”后，Choose 增加 weaponMagnitude 中火球对应的值，下次发射火球时读取。攻击力和攻速按武器分别保存。

### 候选生成与提交

RunProgress.Choices 调用 EmberChoicePool.Build 生成候选，并设置待选状态。卡池根据已有武器、空槽、幸运以及 CanExclusive／CanMetamorph 的结果筛选内容、抽取品质。张数由 ExpectedCount 计算，空槽会增加新武器候选。

卡池以 `(Id, WeaponId)` 去重，同一武器的同一词条在同屏只出现一次。玩家点击后，RunFlowController.IsCurrentlyOffered 校验 `(Id, Rarity, WeaponId)` 是否存在于当前候选，品质也必须一致。

校验通过后，RunProgress.Choose 按卡片类型更新属性，或授予武器、专属、质变，并消耗待选状态。卡面预览只读取这些数据。

### 清波奖励与补偿选卡

清波经 EmberGame.OnWaveCleared 进入 RunFlowController：

1. 从 LevelConfig.PicksAfterWave 取得计划选卡次数，保存在 pendingPicks。
2. RequestChoices 生成候选，OnUpgradeOffered 回调 EmberGame，切换阶段并显示面板。
3. 普通选择成功后减少计划次数；如果首次获得新武器，转入 compensationPick 补发候选。
4. 补偿不消耗计划次数，也不再次触发补偿；结束后决定继续计划内选卡，还是完成整个序列。
5. 选卡结束后，EmberGame 调用 combat.AdvanceAfterUpgrade，再恢复 Playing。

TryRefresh 要求当前处于选卡阶段、存在待选卡且还有刷新次数。刷新会替换候选，Pending 不累加。

## 三、武器与伤害

武器保存各自的冷却、弹体或视图。EmberCombat 按顺序调用武器 Tick，并提供敌人查询、伤害、对象池、特效和音效回调。

共用入口在 `EmberWeapon.cs`、`EmberWeaponFactory.cs`，伤害和火区在 `EmberCombatDamage.cs`、`EmberBurnGround.cs`。

### 武器接口

EmberWeapon 定义 Tick 与 Reset。EmberWeaponFactory.CreateAll 创建六个实现，列表顺序就是本帧的推进顺序。

开局时，EmberCombat 将世界、玩家、相机、池、特效、敌人查询和伤害回调写入 EmberWeaponContext；每帧更新 Progress、Elapsed 和实际 PlayerSpeed。各武器通过这个 context 访问战斗数据。

火球用 FindNearestVisibleEnemy 查目标，命中后调用 DealDamage，弹体视图从 Pool 取用和归还。接触伤害调用 DealContactDamage，音效调用 PlaySound。

### 六把武器

- **`EmberBasicShotWeapon.cs`**：保存 fireTimer 和 Shot 列表。冷却到时找最近可见敌人，建立带速度、寿命和伤害快照的弹体；逐帧移动，检查可见范围和命中，命中或到期后回收。质变命中请求创建共享燃地。
- **`EmberOrbitWeapon.cs`**：保存环绕球视图和燃地间隔。按本局数量补齐视图，用累计时间计算围绕玩家的位置；对每个敌人取最近的接触球结算本帧伤害，避免同帧多球叠加。质变时沿轨迹留火区。
- **`EmberTrailWeapon.cs`**：按间隔在玩家位置请求火区；火环形态另维护 ringView，跟随玩家并结算范围内接触伤害。火区本身由 EmberBurnGround 管理。
- **`EmberPierceWeapon.cs`**：每支 Arrow 记录剩余命中次数、已命中敌人集合和 isSplit。接近静止时才发射新箭，移动后已有箭继续飞行；质变命中产生分裂箭，分裂箭不再分裂。
- **`EmberBoomerangWeapon.cs`**：每只 Butterfly 保存方向、行进距离、返程状态、剩余往返次数及去程／返程命中集合。到达距离后追向当前玩家位置，完成往返后决定再次出发或回收。
- **`EmberMeteorWeapon.cs`**：将目标当时的位置保存为 Strike.point，同时保存倒计时、半径、伤害和预警圈。倒计时结束在保存的落点做范围结算并回收预警，不持续跟随原目标移动。

火球发射时计算“基础伤害 × DamageMul × 单武器攻击力倍率 × 形态倍率”，结果保存在弹体中。命中时再乘当前临时 Buff 的增伤倍率。

### 命中与扣血

EmberCombatDamage.Apply 按下标取得敌人，检查目标能否选中、是否位于判定视口内。通过检查后：

1. 乘玩家当前 BuffManager.DamageMultiplier。
2. 铁灯卫按伤害来源方向计算正面减伤。
3. 扣生命，更新血条和受击反馈。
4. 生命归零时先尝试重生词缀接管，再调用行为 OnLethal。
5. 没有被接管则标记 dead，等待武器推进完成后的死亡处理。

敌人先标记为 dead，全部武器 Tick 完成后再从名册移除，以免改变其他武器正在使用的下标。

### 共享燃地

EmberBurnGround 保存 Flame 列表，每个火区记录视图、寿命和 powerScale；满额时替换最早区域，到期时回收视图与逻辑对象。火球、环火和燃地武器都可调用 SpawnPatch，不要求拥有燃地武器。

EmberCombat 在 EmberTrailWeapon 的推进时隙调用火区 Tick，因此之前火球和环火在本帧创建的火区可参与本次结算。Tick 读取当前构筑，按范围与 dt 计算接触伤害，再进入统一伤害入口。

## 四、敌人与波次

主要脚本：`EmberCombat.cs`、`EmberWaveDirector.cs`、`EmberEnemyRoster.cs`、`EmberEnemy.cs`、`EmberSpawnPlacement.cs`、`EmberPool.cs`。通过 `IEmberCombatHost.cs` 读取阶段、构筑和计时，并请求受伤、拾取或流程切换。

### 刷怪与敌人创建

EmberWaveDirector 保存 wave、waveQuota、waveSpawned、waveKilled、extraSpawned、倒计时和 awaitingUpgrade。StartWave 根据 LevelConfig 判断普通波或 Boss 波，重置计数，安排横幅、生成间隔或 Boss 预警。

普通波的 Tick 检查配额、同屏上限和生成间隔，满足条件后调用 Host 的生成方法。Host 由 EmberCombat 实现，再调用名册创建敌人。生成成功才增加 waveSpawned；没有合法落点就保留配额。遭遇事件也使用这些生成方法。

EmberEnemyRoster 确定敌人种类，调用 EmberSpawnPlacement 查找地图内、完整相机视口外的位置，随后从池取出视图，创建 EmberEnemy，设置血量、速度、词缀、行为、皮肤和血条，加入名册。Boss 使用玩家附近的指定落点，分裂子体允许在母体附近的屏内位置生成。

EmberPool 用 Dictionary 保存各 key 对应的对象栈，取用时优先恢复已有对象。敌人回收还要清理血条和附着表现，避免下次取出叠加或残留上一种外观。

### 敌人行为与 Boss 招式

`EmberEnemyBehavior.cs` 定义 IEnemyBehavior、上下文和策略，CreateBehavior 按 kind 选择：

- ChaseBehavior：基础追击。
- ShooterBehavior：距离、蓄力、射击和技能弹。
- SplitBehavior：死亡回调登记分裂位置。
- ShieldBehavior：盾朝向及正面减伤规则。
- BomberBehavior：接近引爆与致死接管。

EmberEnemy 保存生命、视图、半径、词缀和行为等运行时数据。TickEnemies 遍历名册，推进闪白与重生；有 Boss ai 时调用其 Tick，否则推进普通行为，随后检查接触伤害和灼热范围。

`EmberBoss.cs` 用 AttackState 管理追击、冲锋预警、冲锋、爆发预警、齐射预警和恢复。Boss 同样由名册遍历推进；`EmberEnemyProjectiles.cs` 另管理暗弹移动与命中。带减益的技能通过宿主施加伤害和 Buff。

`EmberEnemyVisual.cs`、`EmberEnemySilhouette.cs` 读取敌人状态，更新皮肤、漂浮动画和攻击预警。

### 死亡、分裂与掉落

武器推进完成后，EmberCombatDamage.ResolveDeaths 倒序处理 dead 敌人：必要时检查重生接管，调用 OnDeath，生成掉落，回收并移出名册，返回击杀数与 Boss 死亡结果。

EmberCombat 据此更新本局击杀和波次计数。分裂请求暂存到 pendingBroods，之后才创建子体并登记 extraSpawned，避免命中遍历中新增敌人。

烬胎母体有两处分裂登记：SplitBehavior.OnDeath 和结算器的 kind 分支。子体数量由这两次登记共同决定。

`EmberDrops.cs` 保存视图、寿命和可选 Buff 配置。死亡时分别判断治疗与 Buff 掉落，Tick 推进寿命和吸附，接近玩家后请求宿主治疗或施加效果，接受后才回收。分裂子体不再产生这类掉落。

### 清波与 Boss 结束

普通波清波需要同时满足三个条件：配额已全部生成、场上没有敌人、尚未进入待选卡状态。清波后清除暗弹，通知选卡流程。

Boss 波从预警开始就标记为 Boss 波，防止预警期间空场误判清波；预警结束后创建 Boss 与伴随兵，再按目标数量补兵。

Boss 死亡后取消待分裂请求，让余兵退场，并移除玩家当前迟缓。余兵退场不补记击杀或另发掉落；阶段 Boss 交回选卡，最终 Boss 进入胜利结算。

## 五、Buff

主要脚本：`BuffConfig.cs`、`Buff.cs`、`BuffManager.cs`、`EmberBuffCatalog.cs`。

### 配置、实例与管理器

BuffConfig 是共享不可变规则，保存 Id、名称、属性、修正量、持续时间与是否减益。Buff 是某个角色的一次生效实例，保存 Config 与独立的 Remaining。BuffManager 保存 active 列表，公开只读视图及汇总的移速、伤害倍率。

EmberBuffCatalog 提供当前复用的增伤、疾行和迟缓配置。不同角色使用同一配置时，仍有不同的实例与倒计时。

### 新增、刷新与到期

1. 掉落或技能请求 EmberGame.TryAddBuff，入口检查阶段和本局是否有效。
2. BuffManager.Add 查同 Id；不存在则创建并重算，存在则刷新 Remaining，不叠加实例。
3. 同 Id 必须使用同一个配置对象，否则抛参数异常，避免同名效果使用不同规则。
4. EmberGame 只在 Playing 调用 Buffs.Tick；到期实例移除后重新汇总属性。
5. 移动和伤害读取最新倍率，界面读取配置与剩余时间。

Add 返回 true 表示新增，false 表示刷新。两种情况都会更新 HUD 反馈，EmberGame.TryAddBuff 均返回成功，掉落物随之回收。

### 属性汇总

Recalculate 从基础倍率开始，累加仍然生效的同属性 Bonus，再做下限限制。效果到期后重新计算倍率，基础移速和武器伤害保持原值。

EmberKeeperMotion.Step 读取 MoveSpeedMultiplier。弹体、环绕接触和共享燃地的伤害经过 EmberCombatDamage.Apply 时，读取 DamageMultiplier。

## 六、界面画面与声音

### UI 绑定与操作回调

`EmberUiRoot.cs`、`EmberIntroView.cs` 保存视图引用，场景引用 `Assets/UI/UIRoot.prefab`、`Assets/UI/IntroRoot.prefab`。布局、图片、字号和静态层级保存在 Prefab。

EmberGame.Start 调用 `EmberIntro.cs` 准备字体并显示加载页。准备完成后调用 EmberMenuUi.Bind，创建 HUD Presenter，等待玩家点击或按键进入菜单。

`EmberMenuFlow.cs` 保存征程、难度、槽位选择，最后将起始武器交给宿主 StartRun；`EmberMenuUi.cs` 绑定通用面板和按钮。界面通过 IEmberMenuHost 请求切阶段或开局。

`EmberHudPresenter.cs` 读取本局、构筑、波次与 Boss，推给 `EmberHud.cs`。条形数值随状态更新，文字和阶段信息按对应数据变化刷新；受伤、拾取和选择后也主动 Push。

`EmberOfferPresentation.cs` 生成 Title、Description、NumericPreview 和 Badge。`EmberUpgradePanel.cs` 用这些内容填充候选卡，调整排布并绑定选择、刷新回调；`EmberCardMotion.cs` 负责动画。玩家确认选择后，由 RunProgress 更新构筑。

### Buff 显示、设置与安全区

`EmberBuffPresentation.cs` 从效果定义生成说明；`EmberBuffHud.cs` 按 Id 绑定图标、计时环和秒数，并复用浮字槽位。Presenter 传入 Active 和角色位置，UI 不推进效果计时。

`EmberSettingsPanel.cs` 读取音量与 GameSpeed，按钮和滑条修改对应对象；继续或返回通过传入回调执行。`EmberSafeAreaWatcher.cs` 观察安全区与分辨率，只在变化时通知重排。

### 角色与场景外观

`Assets/Art/HandPaintedSample/ArtSet.asset` 通过 `EmberArtSet.cs` 提供玩家、敌人和庭院模板，StartRun 实例化到本局世界；未指定玩家模板时创建原版外观。

当前玩家帧图与动画在 `Assets/Art/CleanToonSample/Player`，角色模板在 `Assets/Art/CleanToonSample/Prefabs`，皮肤和盾图在 `Assets/Art/CleanToonSample/Enemies`。项目还保留原版角色和手绘分件角色。

`EmberKeeperAnimation.cs` 在 LateUpdate 根据实际位移计算速度，设置 Animator 的 IsMoving 参数，并按横向速度和默认朝向控制 flipX。Animator 平时 speed 为零，由组件在 Playing 时手动 Update；帧图路径不再给整张角色叠加位移、倾斜和缩放。

`EmberKeeperRig.cs` 驱动分件动画，EmberKeeperMotion 移动角色根节点。`EmberEffects.cs` 管理粒子，通过传入的阶段函数控制更新。

### 图集、字体与音频

EmberWorldArt、EmberUiArt、EmberCardIcons、EmberCardFrames、EmberPickupArt 分别读取场景、UI、卡牌和拾取物资源。EmberBakedArt 优先加载预烘图元，加载不到时使用 EmberArt 等代码生成图形。切片身份和导入设置保存在 .meta。

`EmberFonts.cs` 检查预烘 TMP 字体，通过 ValidateBaked 后才交给 UI，缺失或检查失败则回落动态路径。`EmberCopy.cs`、武器文案和效果名称共同影响所需字形。

`EmberAudio.cs` 创建音乐和音效 AudioSource，通过 Resources 加载素材，分别管理音量并写 PlayerPrefs；菜单与战斗切换音乐，密集音效用非缩放时间节流。缺失素材告警后跳过。

## 七、单局流程与配置

主要脚本：`EmberGame.cs`、`EmberRunState.cs`、`EmberRunPhase.cs`、`IEmberRunPhaseSource.cs`、`LevelConfig.cs`、`GameSpeed.cs`。

### 启动与开局

场景中的 EmberGame 负责初始化和每帧调用。Awake 创建 EmberRunState、RunFlowController 和 EmberInput；Start 初始化音频、相机、战斗、菜单和加载页，UI 准备完成后进入菜单。

EmberRunState 保存构筑、配置、生命、Buff、计时、击杀，以及 World、Keeper、Cam、Effects 等引用；具体生命、升级和选卡规则由对应对象处理。

菜单完成选择后调用 StartRun：

1. 检查 UI 和 ArtSet，按选择创建 LevelConfig，重置选卡流程。
2. 关闭并销毁旧世界，再建立 World 和 Effects。
3. 创建新 RunProgress，清 Buff 与击杀，重置生命。
4. 实例化庭院与玩家，连接外观的阶段函数。
5. 应用地图配置，combat.Begin 绑定名册、池、波次和武器服务。
6. 相机对齐，SetPlaying 收起面板、应用倍速并显示 HUD。

### 每帧更新顺序

EmberGame.Update 只在 Playing 阶段执行。先累计本局时间、更新无敌帧并读取输入，确认仍处于战斗阶段后，依次更新 Buff、玩家移动、相机和战斗，最后更新浮字反馈与 HUD。

EmberCombat.Tick 先更新波次和掉落，再移动暗弹、执行敌人行为和接触伤害，随后处理灼热范围伤害、武器和共享燃地，最后检查暗弹命中、处理敌人死亡和清波。

输入可能触发暂停，受伤可能结束本局，因此执行中会重新检查阶段。角色外观、粒子、安全区和界面动画在各自的 Unity 回调中更新。

### 暂停、结算与返回

Pause 将阶段设为 Paused，清空拖动输入，隐藏 HUD 和摇杆，打开设置页。点击继续调用 SetPlaying。本局 Update、角色动画和粒子都检查阶段，暂停时停止更新；Time.timeScale 保持所选倍速。卡片、加载页和音效节流使用各自的非缩放时间。

EndRun 将阶段设为 Won 或 Lost，播放菜单音乐并显示统计，保留本局世界。结算页的“重新开始”进入选局流程，“返回营地”调用 ReturnToCamp。

ReturnToCamp 恢复基础 timeScale，清输入与选卡流程，隐藏面板，combat.TearDown 拆除战斗，销毁 World，再通过 Run.Clear 清本局数据和场景引用，最后显示菜单。场景 UI 保留供下一局使用。

### 配置与倍速

LevelConfig 保存难度、地图、波次、敌人、Boss、遭遇和掉落配置；Create 建立本局配置，战斗通过 QuotaForWave、SpawnInterval、TrashHp 等方法读取。ApplyWorld 将地图限制写入空间辅助代码。

EmberWeaponTuning 保存基础武器参数和共享升级增量，供构筑、攻击与卡面预览共同使用。

GameSpeed 将所选倍率写 PlayerPrefs 并应用到 Time.timeScale。SetPlaying 再次 Apply，避免返回流程重置时间后丢失选择。
